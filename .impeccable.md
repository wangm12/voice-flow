## Design Context

### Users

macOS developers and knowledge workers who dictate into whichever app currently
has focus. They need fast, glanceable feedback while keeping their attention in
Cursor, an editor, a browser, email, chat, documents, or another productivity
app.

### Brand Personality

Fast, calm, trustworthy.

### Aesthetic Direction

A compact, dark OLED voice HUD inspired by the supplied Gemini Live / Typeless
reference: a compact 132×40 pill, restrained contrast, clear state changes, and
quiet system-level presence. Settings use neutral white-gray surfaces in light mode and black-gray surfaces in
dark mode, following the user-approved Codex screenshot and paired color preview. Actions, links, selection, and focus stay monochrome. Blur, large glow stacks, and motion that costs
responsiveness are deliberately avoided on the always-on-top transparent panel.

### Settings System

References: [Apple palette analysis](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/apple/DESIGN.md)
and [Cal.com control analysis](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/cal/DESIGN.md),
adapted to VoiceFlow’s existing desktop and website.

Use #FAFAFA with #202020 text, #FFFFFF task surfaces, and a #F1F1F1 sidebar in light mode. Use #171717 with #ECECEC text, #282828 task surfaces, and a #1B1C1D sidebar in dark mode. Primary actions use #202020 / #FAFAFA labels in light mode and #EDEDED / #1D1D1D labels in dark mode; hover is #333333 / #DADADA and pressed is #454545 / #CACACA. Links use the main text color; focus is #606060 in light mode and #D5D5D5 in dark mode. Selected rows use #E3E3E3 / #333333. Inputs, neutral buttons, shortcut recorders, and switch tracks use quiet filled surfaces. Dropdown triggers and editable suggestions have one faint border and a chevron; their shared portaled menu uses a 16px corner, a selected-row fill, a trailing checkmark, and restrained shadow. All 29 fixed selectors and three editable suggestion fields share these rules across settings and onboarding. Pointer interaction never draws a focus box around the selected menu row; keyboard navigation retains a clear single indicator. Editable suggestions preserve arbitrary input and validation; fixed selectors preserve empty default values and disabled choices. Menus dismiss with Esc/outside clicks, return focus, and fit the available window area. Focus uses a single 2px outline at the control edge, with no second border, shadow ring, or offset gap; invalid and verified fields reuse that one outline for their semantic state. Shortcut recorders and segmented choices use quiet filled surfaces without nested borders. Selected activation choices combine a filled state and a checkmark; shortcut key labels stay unboxed inside one surface. Action, danger-action, and switch-thumb foregrounds have separate roles; checked switches keep a near-white thumb in both themes. Keep
success, warning, and error colors semantic. Render optional help only when it has content so continuous rows do not gain empty dividers. Keyboard focus and active shortcut recording retain a visible 2px outline.
Destructive confirmation uses a filled red action with near-white text; inline
delete actions stay lighter. Both share disabled, busy, and focus behavior.

Use the 4 / 8 / 12 / 16 / 24 / 32 / 48px spacing scale: page padding 32px
(24px in narrow windows), setting rows 16px vertically and 20px horizontally,
groups 24px apart, and labels 8px from inputs. Standard controls are 40px,
compact actions 32px. Use 12px control and 16px group, menu, and dialog radii. Ordinary groups use one white/dark task panel with a faint border and continuous rows separated by fine lines. Nested groups within a disclosure stay flat, without a second enclosing border. Shadows belong to floating menus and dialogs. System type uses 28px page headings, 14px
controls, 13px descriptions, and 12px auxiliary text. The HUD keeps its own
native dimensions and typography. Its neutral #202020 surface, #E8E8E8 labels, and monochrome border beam are shared by the product, onboarding, and website.

Center the orb and status text together as one intrinsic-width group inside the HUD. Text-only states must not reserve an empty orb slot. Crossfading labels overlap in one grid cell so the outgoing label keeps its full width. Onboarding and website previews share the product's 132×40 geometry, padding, and alignment.

The desktop frame fills a fixed native settings window: 1035×750 logical content pixels by default, with drag resizing, zoom and native fullscreen disabled. On macOS, extend content to the top without a separate titlebar, repeated window title or header separator. Keep native controls above the sidebar brand, reserve their space in settings and onboarding, and use the quiet top whitespace as a shared drag region through loading and errors. Other platforms retain their native titlebar. Fit smaller displays to their usable work area, accounting for scaling, native frame and Dock; recompute when changing displays or reopening settings. Anchor the 224px navigation sidebar to the left window edge; keep settings content aligned to the sidebar with one page inset and a 768px usable maximum width. Small-screen adaptation must not add a second centered outer frame or duplicate content padding. Recording mode offers exactly two enabled choices, Tap to toggle and Hold to talk, for both Fn and combinations. Choices share one borderless segmented surface with native radio keyboard behavior, a selected checkmark, visible keyboard focus, and the current binding's instruction plus Esc cancellation beneath it. Binding capture never infers or changes the recording mode. Keep an explicit Fn choice, contextual macOS conflict note, and Keyboard settings entry. Preserve deprecated single-modifier bindings visibly with rebind guidance. Disable binding and mode changes during recording or processing, and commit page values only after the native transaction succeeds.

All component styles follow the user-provided Codex settings and microphone-menu screenshots: neutral fills, faint structural borders, one focus indicator, consistent typography and spacing. Shared Select and Autocomplete components use Radix interaction/positioning primitives with VoiceFlow-owned styling; no Codex source is copied. Keep labels and saving semantics specific to VoiceFlow.

The content area is a CSS container: below 560px, selectors and long fields move below labels while switches and short actions stay inline. Standard selectors are 160px, devices/models 220px, and number fields 88px. Keep groups inside disclosures visually flat, with a single row inset rather
than repeated card borders and padding. Onboarding footer actions share the
content's maximum width, page inset, and scroll gutter; actions wrap when space is limited. Task steps stay aligned to the sidebar, while the welcome message and its footer share a narrower centered column. Neutral buttons and
icon actions have distinct pressed feedback; checked switches use a near-white thumb.
Reserve a stable scroll gutter so switching between short and long pages keeps
the content aligned. Show full microphone names beside their selection, with
current and explicitly selected devices labeled separately. Busy controls keep
their width; export and text-action feedback stays beside the action.
Entering service settings starts with its overview; opening provider management
keeps focus on the disclosure. A changed service can guide to its missing key.

Present everyday tasks first and progressively disclose advanced settings.
Disclosures preserve mounted content and drafts, introduce no save or request,
and preserve normal blur commits. Errors open their group. Shortcut capture
locks its group through preparation, recording, completion, and native hotkey
restoration. Idle shortcuts are compact clickable key chips, with an edit icon on hover or keyboard focus. Editing replaces the chip with an inline capture field, the current binding, and explicit Fn/cancel/default-reset/optional-clear actions. Capture only from the field; Tab and Shift+Tab navigate normally. Escape, outside interaction, focus leaving the group, or switching apps cancels capture. Keep the saved value until native registration and persistence acknowledge, show progress and friendly errors beside the control, and never reclaim focus after the user has moved elsewhere. Physical key codes preserve Option/Shift chords; new bindings require Command/Option/Control or a function key, with Fn explicitly selected for recording. Native keyboard state decides when the full chord has released before registration and saving; do not depend on WebKit delivering every release. Serialize native capture across page changes, including late acknowledgments; changing a binding never changes the recording mode.
Keep tone selection and its single manual preview outside the
Prompt disclosure, with existing draft comparison and cancellation behavior.
Tone selection explicitly chooses which tone to edit; it does not change active dictation. Label preview results as saved configuration or current draft. Provider editors retain one keyed instance per provider when configuration changes. Provide the same tone-save action beside the Prompt editor so users can finish
editing without scrolling back to the preview.
Keep privacy grants, offline controls, storage, and model download state visible.

History keeps query order and pagination, adding a local-date heading only when the adjacent date changes. Copy, editing, and available recovery remain visible; low-frequency actions use a shared menu with arrow-key navigation, Escape, and focus return. Copy feedback stays in place for two seconds. Disabled controls use dedicated colors instead of dimming the whole control.

Background settings snapshots reconcile tone ids and content while preserving active drafts. Confirmation actions resolve against current state. Errors belong beside their controls; collapsed groups reveal the actual error. Edit and preview cancellation return focus to their entry controls. Busy widths belong to each action, with no global minimum overriding them. Text-operation previews lead with the editable result and disclose source details in the same scroll area.

HUD captions use short, actionable copy; full delivery reasons remain in History and accessible descriptions. Long processing captions and recording-limit guidance share the wide native geometry. Learning prompts expand the native window to include their controls, then restore its normal size when dismissed. Learning Undo remains available; delivery Undo has no HUD entry.

Settings layout references include the official Typeless settings guide, Raycast Settings, Wispr Flow desktop navigation, Superwhisper modes, and Things feature screenshots. Borrow row alignment and task clarity, while preserving VoiceFlow saving, permissions, and privacy semantics.

### Design Principles

1. State feedback must be immediate and legible without stealing focus.
2. Context adaptation should be visible but conservative: preserve the user's
   intent when confidence is low.
3. Motion communicates recording, processing, completion, and failure; it never
   competes with the active application.
4. Privacy and target safety are product-facing behaviors, not hidden plumbing.
5. Every fallback keeps the user's text recoverable.

### Marketing Website

The independent `website/` targets the same macOS developers and knowledge
workers, with Chinese as the initial language and an English switch. Its voice
is fast, calm, and trustworthy. The homepage follows Typeless's oversized
typography and generous whitespace; VoiceFlow uses its approved neutral palette and deep-gray, 8px-radius download buttons, with product
storytelling inspired by Wispr Flow and Chinese usage examples inspired by
Typefree. Use the same #FAFAFA background, #202020 text, white surfaces, and deep-gray
actions as settings. Demo and story surfaces use neutral grays; color is reserved for semantic status and native macOS traffic lights. Keep the site light, with a dark privacy section, fine
borders, a 1280px maximum content width, 20/32/48px responsive gutters, 64/80/96px section spacing, 48px primary actions, and clear hover and focus states. English headings use Sora, body text uses Figtree,
and Chinese uses Noto Sans SC; fonts are self-hosted.

The preset browser demo shows speech, optional cleanup, and finished writing
without microphone access or provider requests. Product and privacy copy must
match the living docs. Use alternating feature layouts, purposeful state
motion, accessible focus, and reduced-motion support. Avoid invented customer
endorsements, certifications, or performance statistics.

The main demonstration should visibly animate as soon as it enters view:
progressive speech highlighting, the actual product HUD, a brief cleanup state,
and progressive writing. Hold the result before looping. Keep pause, resume,
and replay controls visible. Pause offscreen and in background tabs; reduced
motion defaults to a static result. Feature illustrations reveal once on
scroll. Motion is part of the product story, not only hover feedback.

The website HUD reuses the product's pure React orb, state configuration, beam
geometry, and island styles. Keep the native 132×40 dimensions, system font,
Listening… / Thinking… labels, breathing / shaping orb states, and completion
fade. The website clock may loop its preset story, but should not invent HUD
waveforms, stop buttons, or persistent success indicators.

Use Hugeicons Stroke Rounded for website UI icons: 1.5 stroke, currentColor,
rounded geometry, and a small size scale of 16 / 18 / 20 / 24. Keep decorative
icons out of the accessibility tree. Brand marks and the hand-drawn VoiceFlow
story illustrations retain their identities. On mobile, keep touch targets at
least 44×44, explanatory text at least 12px, and reading text at least 14px.
