# VoiceFlow 纠错 Harness 生产接入与规则晋升研究计划

状态：研究提案，待实施。基线：本地 `main` 的 `6cbef2b`。完整实验未运行。

## 1. 研究目标

用户把听写里的一个词改对后，VoiceFlow 应该能在下次相似听写里少犯同一个错。同时，用户补充一句话、改主意，或修复 cleanup 的改写，都不应把错误规则写进个人词典。第一阶段固定 ASR 和 cleanup 模型、prompt、输出模式及强度，研究变量仅为编辑证据、归因和规则生命周期。

- **H1 归因**：比较真实交付路径和独立原话参考，可以减少把补写、本机规则误改、cleanup 误改和目标应用自动格式化当作 ASR 纠正的情况。
- **H2 晋升**：作用域内重复证据加反例验收，可在减少误改的同时保留未来纠正收益。
- **H3 保守边界**：日常使用缺少独立原话参考时，自动覆盖率可能下降。单独量化这项代价，再决定是否启用更严格的生产门槛。

`main` 的旧词典写入路径会将晋升结果写入全局词典，无法作为 V2/V3 场景内词对的等价替代。旧版 History 打开逻辑也可能把较新数据库的 `user_version` 写回 13。存储迁移验收必须包括新库升级、旧构建打开副本、失败恢复和降级操作说明。升级产物只在临时数据库验证。

C0 待验证的顺序是短录音和长录音的实际完成入口产生 origin，History 保存和 paste 观察再引用同一个 origin。覆盖两种提交顺序、重复回执、History 删除和重启恢复。单独回归两个兼容问题：

- 手动添加的 Settings 保存失败时，即使另有待同步的数据库动作，也要如实报告本次添加失败。
- 带有 `github`、`GitHub` 等旧词面的词典迁移后，校验已存在的规则仍可按原作用域匹配。

## 3. 参考研究与取舍

`0shot RL` 在此作为「模型权重固定，从反馈改进后续任务」的工作假设。若有明确指定的项目或论文，补做机制和证据核对。

| 参考 | 可借用的机制 | VoiceFlow 的实现边界 |
| --- | --- | --- |
| Reflexion | 用任务反馈形成可在以后召回的经验 | 经验保存为可追溯的词对或结构化回归记录。只有适用场景召回对应词对 |
| Harness Continual Learning | 将提出更新与允许更新生效分离，检查当前收益和历史能力保留 | 同一候选先过正例和历史保护反例，再进入有作用域的规则集合 |
| Test-Time Harness Evolution | 从运行轨迹生成外部 harness 更新 | 轨迹适合定位问题和生成候选。归因与自动写入需要独立证据 |
| SCoRe | 多轮训练提升模型自我纠正能力 | 作为训练层研究对照。本计划的实验变量是应用层，不安排权重训练 |

原始来源：[Reflexion](https://arxiv.org/abs/2303.11366)、[Harness Continual Learning](https://arxiv.org/abs/2608.19013)、[TTHE](https://arxiv.org/abs/2607.08124)、[SCoRe](https://arxiv.org/abs/2409.12917)。

## 4. 一次编辑如何变成下一次的候选规则

```text
录音 -> ASR -> 本机预处理 -> cleanup / guard -> 实际交付 -> 同字段观察
          |          |              |              |           |
          +----------+--------------+--------------+-----------+
                                    |
独立原话参考 ---------------------->+
                                    |
                          对齐来源、阶段和编辑范围
                                |
                       确定性归因 + 弃权原因
              +-----------------+------------------+
              |                 |                  |
       ASR 词汇纠正       预处理 / cleanup 误改   补写 / 未知
              |                 |                  |
        场景内候选         对应层回归用例         本次编辑结束
              |
   独立证据去重 -> 正反例回放 -> 晋升 -> 下次匹配 -> 挑战 / 撤销
```

### 4.1 各层证据

| 层 | 可用于归因的最小证据 | 生命周期 |
| --- | --- | --- |
| 来源 | 听写事务 ID、试验 arm、场景 ID、配置代际、输入来源及授权 | 日常记录优先复用现有 opaque ID。实验 ID 与生产隔离 |
| 独立原话 | 来自合成夹具或审核人员的原话、审核来源和范围 | 隔离语料库。需要比较原话但缺参考时为 `ReferenceMissing`。交付后完全没改可直接判 `Unchanged` |
| ASR | 原始转写、模型及路线身份、阶段是否成功 | 文本限本次授权处理或隔离实验。模型和配置身份用于重现 |
| 本机预处理 | 准备稿、实际规则 ID、变更前后范围 | 规则 provenance 由执行 owner 提供，无法唯一关联时标记未知 |
| Cleanup | 模型候选、模式/强度、是否跳过、guard 接受或拒绝原因 | 模型候选和实际采用稿分开。回退记录最终采用哪个阶段 |
| 交付 | 是否确认写入、原目标身份、插入范围、首次可信回读、实际交付文本 | 复用现有回读凭证与权限代际。失焦、过期或来源冲突时终止 |
| 编辑 | 同字段局部差异、稳定窗口、候选范围、结束原因 | 仅在允许范围和有效期内读取。完整字段留在当前处理内存 |
| 判定 | verdict、reason、first_difference_stage、所用证据、是否能提议词对 | 旁路优先仅保留汇总或短期结构化结果。详细文本仅进入授权实验 |

区分 `skipped` 和 `missing`。前者是有证据表明阶段没执行，后者表示证据不足。拒绝的 cleanup 候选可以成为未交付回归。用户编辑归因沿实际采用的回退稿判断。完整 AX 字段、录音、模型输出和用户编辑都可能包含敏感内容，生产旁路默认无需新增持久化文本。

当前纯裁判只接受本次插入恰好覆盖首次完整字段快照的情况。已有内容的输入框如果只插入其中一段，会返回 `RangeUnsupported`。R3 首轮按完整字段、部分插入分别报分母和覆盖，部分插入支持单独立项。验收时须证明范围随编辑可唯一追踪，同时禁止把原有文本或范围外新增内容当作本次听写证据。

### 4.2 判定表

| 观察到的证据 | 归因 | 处理 |
| --- | --- | --- |
| 原话有词，ASR 首次漏掉，后续也没恢复，编辑补回原话 | `ASR_OMISSION` | 统计漏听与评测。第一版纯插入不自动建立词对 |
| 原话、ASR 和交付一致，独立标注确认用户后来加了新内容 | `USER_ADDITION` | 本次编辑结束 |
| 原话和交付一致，但编辑意图没有标签 | `CONTENT_EDIT` 或可解释的 `UNKNOWN` | 无自动词对 |
| 原话支持正确词，ASR 首次错词，实际交付仍保留错误，稳定编辑正好改回 | `ASR_SUBSTITUTION` | 提议词对，另过候选准入 |
| ASR 正确，本机替换首次改错，范围能绑定到规则 | `LOCAL_PREP_REGRESSION` | 向该规则记录挑战证据，无反向自动规则 |
| 准备稿正确，cleanup 候选改错，实际交付采用了该差异 | `CLEANUP_REGRESSION` | 进入 cleanup 保真或格式回归组 |
| 参考、层级或来源缺失，含重复词对齐歧义，或仅观察到 IME 中间态 | `UNKNOWN` 加具体原因 | 无自动写入，按原因统计覆盖缺口 |

旁路只用日常 observer 已有权限处理本次会话内存中的证据。真实结果用于研究采样或保留时，依 §5.3 独立核实授权。若后续需要第二个本机 ASR 或小模型协助，它只提出调查线索。候选模型和同一音频的其他输出不能自行升级为人工 gold。用户在现有词典入口明确确认一个词对，可作为用户规则写入。显式确认和独立 ASR 证据分别计数。

### 4.3 晋升、检索和撤销

1. **提议**。第一版只接受有可靠归因的单个完整 ASR 词汇替换。观察器提取的 before/after 与裁判一致，场景匹配，日期、金额、否定和普通内容编辑另行评估。旧版 scope 的兼容性由迁移测试证明。
2. **记证据**。独立单位是有真实来源绑定的听写 origin。paste 和 History 回执同一次听写只计一票。重复操作、研究 apply/undo 收据、遗留无来源记录不作为独立票。当前普通词 3 次、人名 2 次作为对照门槛，实验开始前冻结。
3. **对照**。用开发集中的后续输入重放候选正例、无关正确文本、其他 App/场景、大小写和同音词。包含「李明」与「黎明」均正确的样本。出现错误替换、语义改动或跨范围命中时保留待复核状态。最终留出集只评估已经冻结的候选与策略。
4. **应用**。从同一授权规则集合做检索和替换。记录候选被取出、确定性替换、被最终保留和写入确认四件事。未来同类输入被修好才计入实验收益。
5. **纠错规则本身**。用户把已应用词改回时，只有能关联到实际命中的规则且解释排除了内容编辑，才计入挑战。撤销与忽略复用现有 tombstone 写入。撤销后手工词条和其他来源贡献仍保留，是 C0 的验收条件。自动挑战暂停策略先在隔离 arm 评估。

## 5. 实验与验证

### 5.1 三组对照

| Arm | 配置 | 要回答的问题 |
| --- | --- | --- |
| A | 当前观察和词对门槛的基线快照 | 现有提取、写入和未来纠正的精度与覆盖 |
| B | 同一观察器，加确定性归因准入 | 多拦截了哪些误学，代价是漏掉多少真正纠正 |
| C | B 加场景约束与候选保护反例验收 | 能否进一步降低误改，并在未见输入上保留收益 |

各 arm 从同一初始 Settings 和 SQLite 快照独立启动，语料顺序、模型、prompt、模式和强度一致。开发和调参集与最终评测集按 episode、说话人和词族分组隔离。最终评测内部，同一词对先经历学习 episode，再由不同音频及无近重复的独立输入测试召回。规则在学习 episode 按冻结策略晋升，晋升检查只能消费开发保护集及截至该时点的证据。后续召回结果只计分，不回流到本轮规则或门槛。保留每次失败。

### 5.2 分层验证矩阵

| 阶段 | 输入与隔离 | 验收证据 |
| --- | --- | --- |
| R0 纯裁判 | 合成 stage、独立预期标签。无需 Tauri、provider 或 SQLite | 同一 edit diff 切换上游证据得到不同 verdict。验证 fallback、错 origin、重复词、越界、CJK 和 UTF-8 字节边界 |
| R1a V2/V3 协议回归 | 有序字段快照、临时 SQLite 与 Settings，实际 stdio | 保留既有消费、轮询和末尾快照复用语义。正例通过 owner 读回候选、晋升、后续应用、撤销和重开结果 |
| R1b 归因轨迹证据 | 有序字段快照、模拟时钟、临时 SQLite 与 Settings、明确 fixture 授权 | 验证 AX 使用的 UTF-16 范围转换。显式读数足以证明稳定。归因 adapter 的自动重复最后快照不能补足证据。未知和不准入用例零学习写入 |
| R2 迁移和接线 | 从实际旧版 schema 创建临时库，覆盖两种听写完成路径和 History 命令的隔离 fixture | 同 origin 跨通道只有一票。手工词条存活、旧收据不冒充证据、删除级联、重启后幂等、失败可诊断、降级行为明确 |
| R3 只判定的旁路 | 先用合成和已授权重放。具备单独授权后，再用 opt-in 原生采样 | 旁路自身零规则写入。记录与旧逻辑的分歧、弃权原因、真实可测覆盖及额外时延。既有写入与旁路日志分别统计 |
| R4 未见语音和长期收益 | 固定版本的独立审核语料。先用本机路线。隔离凭据、provider、缓存与结果目录 | 同一词对的未来纠正成功、正确样本保持、跨场景边界与撤销。可选原生 E2E 需证明同目标、写入、回读和停止条件 |

合成 R0/R1 的最小反例包括同一编辑 `Deploy today → Deploy today after lunch` 的事后补充、ASR 漏听、预处理误删和 cleanup 误删，以及 `VoiceFlo → VoiceFlow` 的授权、scope、错误来源和回退路径正反例。另加失焦、目标换窗、仅一个变化读数、IME、短语内部重复词、应用自动格式化、范围外打字和字段未确认写入。R0 负例断言 verdict、原因和是否提议词对。R1b 对无写入负例另断言 writer 未进入及学习状态无变化。可学习正例断言状态读回及实际应用效果。

### 5.3 语料、标注和权限

- 首批音频候选为 ASCEND 中英混合对话，以及 Mozilla Common Voice 的合适语种与任务。先固定语料版本、来源、许可、SHA 和用途。ASCEND 可复用现有公开语料准备工具。Common Voice 保持候选，另定导入和授权流程。 [ASCEND 论文](https://aclanthology.org/2022.lrec-1.788/) · [ASCEND 数据卡](https://huggingface.co/datasets/CAiRE/ASCEND) · [Mozilla Common Voice](https://commonvoice.mozilla.org/about)
- 公开语音提供原话参考。App 写入、用户后来补充与真实更正意图需要独立标注。由两名审核者先独立判断原话和差异层，再处理分歧。意图缺证据记未知，仲裁过程与最终标签分开保留。
- 运行目录使用私有临时 arm。音频、完整轨迹、人工标签、凭据和报告原始内容放在仓库外。研究和产品使用的 Settings、History、Keychain、剪贴板与缓存分别隔离。没有可验证隔离证明的用例记为 `not_run`。普通 App 未授权数据不进入研究。
- 当前交付范围为 Git 切分和计划。真实语音、原生目标、云端调用或线上采样属于后续需独立核实的验收阶段。

### 5.4 指标与停线规则

- **归因**。按类别报告精度、召回、混淆矩阵和 `UNKNOWN` 覆盖率。单独报告参考缺失、交付未确认、编辑未稳定和范围歧义。
- **学习**。以独立 origin 为单位报告候选/晋升精度、重复计数、自动覆盖、首次证据到生效所需的次数与时间、确认成本。
- **收益**。按预冻结定义对未来样本的词对机会计数。分别报修好的样本、原本正确且保持的样本、被改坏的样本、撤销后的再次命中。按语种、模型、场景、词族和难度分层并报告分母与置信区间。
- **开闸条件**。合成保护集零误学、零重复票、零越界读写、零跨场景错误应用。打开留出集前，在实验 manifest 冻结各组的误学率上限、最低净收益、覆盖率底线、额外 p95 时延预算、置信区间算法和独立样本簇数。留出集先检验普通文字、专名、数字、否定和目标保护等硬门槛，再按冻结阈值判断净收益。零失败也须报告分母和置信上界。门槛未冻结或样本不足时，结论是待验证。
- **停线条件**。发现未经授权的采样、来源混写、错误自动晋升、迁移导致旧词丢失或数据目录隔离失效，立即停在当前阶段。恢复依赖现有撤销/禁用入口和经过验证的迁移恢复方案。

## 6. 推荐交付顺序

1. 保持 `main` 的纯归因基线，核对待合入改动的依赖和归属。
2. 先送可独立审查的交付 origin 与 History 收据前置，再送 C0 migration 与两条写入接线。每笔在干净基线构建，带对应的临时数据库证明。
3. 接回现有确定性文本 CLI 和受控轨迹。V2/V3 的场景替换、应用收据、撤销和重开全部通过后，再处理与原生或 WAV 有关的扩展。
4. 接正式旁路，只产生归因与拟议行动。先比较三组隔离 arm，冻结指标和分歧样本。将真实样本和生产开关的结论作为单独验收。
5. 只有数据证明正反例均通过，并且旁路未导致不可接受的覆盖损失，才考虑在明确作用域内启用新自动晋升。保留关闭和撤销路径。
