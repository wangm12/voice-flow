# VoiceFlow 改进计划：从 Chatterfly 研究到可验证的产品提升

- 日期：2026-10-26。
- 状态：M2a 已合入当前工作区，相关 L1 定向验证通过；未发布。完整 M2/G2 及其余阶段仍待验收，本文的产品指标尚无达标结论。
- 审查：已由 GPT-6.1 Sol / ultra 独立只读审查并完成补丁复核，提出的 2 个 P1、4 个 P2 均在计划层面解决；这不代表实现或运行验收已通过。
- 范围：macOS 桌面产品、现有听写与有限文本操作。
- 生命周期：进行中的临时计划。相关工作全部落地或明确终止后，删除本文和文档索引入口；实际行为转入活文档，Git 保留过程。

## 1. 要交付的结果

让用户更快得到可信、可直接使用的文字，并更容易发现已有的文本操作。沿用当前 React/Vite + Rust/Tauri、语气、上下文授权、词典和交付机制。

三个核心结果：

1. 用冻结的真实音频与任务集，量出中文、中英混合、改口和文本整理的质量，定位最值得修复的问题。
2. 用户能通过三个明确的整理模板使用已有文本操作，首次听写与失败恢复的下一步更清楚。
3. 把质量、停止说话后的等待、交付正确性和新用户表现分开验收，不用单测数量或功能数量代替体验。

两个有条件的候选方向：

- 停顿时提前整理：先验证可复用性、收益、额外费用与取消可靠性，通过门槛后再接生产路径。
- 仅 HUD 展示流式草稿：先解决提供方文本语义、代际隔离和阅读体验，再决定是否交付。

核心体验改善与候选实验分别结项。实验得出“不值得做”的结论是有效研究结果，但不能算作时延或流式体验已经改善。

## 3. 范围与不变条件

### 本轮包含

- 基线、受控数据集、质量与端到端测量协议。
- 基于评测证据的有限质量修复。
- 三个显式整理模板、示例、预览标识。
- 首次有效听写与失败后下一步的简化。
- 场景、整理回退、学习规则的用户说明。
- 有独立准入门槛的停顿预处理与 HUD 草稿实验。

### 本轮不包含

- 联网问答、任意工具执行、跨 App Agent、会议自动录制、完整拼音输入法。
- 托管免 Key 服务、计费账户体系、新增模型供应商、默认模型更换。
- 统一短按/长按双手势、官网改版、自动发布或自动创建 PR。
- 为提高通过率而放宽事实保护、目标校验或模糊成功文案。

### 所有阶段必须保持

1. 默认听写不截图；AX、本机 OCR、云端视觉、文字发送和风格样例继续独立授权。
2. 不为实验自动读取私人 History、剪贴板、Keychain、录音或任意窗口；凭据沿原通道使用。
3. 不把 provisional ASR 文字写入目标 App、剪贴板、History、词典或普通 cleanup。候选实验也不能绕过这一边界。
4. 文本操作保持预览、显式确认和原目标/原来源复核；失配时按现有规则降级，避免重复写入。
5. 学习仍限已获准的同框观察；保存、候选、晋升、参与筛选和实际替换分别表述。
6. 保持当前 HUD 的 220×48 主体、处理中统一文案、确认输入后立即隐藏及不抢目标焦点的约定。
7. 所有新能力都有关闭或回退路径。关闭实验后不得残留后台请求、草稿、缓存可用标记或新的授权。

详见 [隐私边界](privacy.md)、[以后再做与明确不做](asr-cleanup-later-and-wont.md)、[设计上下文](../.impeccable.md)。

### 4.1 协调实现切片（2026-10-26）

任务「规划语音输入软件逆向研究」（`01a13373-ce14-7323-a3ce-aeb102217f86`）承担 M0a、M0b、M1、M3 与 M4 的重叠生产目标；本任务已合入 M2a 的三个封闭 `Organize` recipe 及现有预览中的有限元数据。两条工作围绕相同产品目标并行，但各自的数据准入、实现范围和验收独立。M2a 由 GPT-6 Luna / max 实现，GPT-6.1 Sol / xhigh 独立复核与验证。

M2a 是完整 M2 的严格子集：recipe 只增加固定标题与按已有空行分段的列表标记，正文保留原词句、标点、空白、换行和来源顺序；单段文字仍是单个条目，不推断字段或改写任务。G2 的模型任务集、原生 App 验收和至少 8 名用户的发现/使用验收仍待完成，代码候选不能代替这些结果。X1/X2 在本切片不启用。

## 5. M0a / M0b：建立可信基线与裁判

M0a 是所有阶段共用的构建、指标和准入协议；M0b 才是完整的真实语音质量基线。M0a 可以先用明确标为 pilot 的受控 fixture 走通方法，不因此宣称 M0b 或模型质量已验收。

### 5.1 怎么改

- 复用现有 evaluator 的 manifest、corpus sidecar、recipe、身份与报告格式。可在 `scripts/research/` 增加离线汇总/盲评辅助脚本，保持 Rust 对评测输入契约的所有权。
- 第一轮只增加缺失的汇总或评审能力。现有 `metrics.rs` 已有分阶段时延、P50/P95、StopToInsert 和用量，不再实现一套统计器。
- 现有用量汇总主要是 ASR，不是完整 LLM 账目。X1 需要补充的 typed attempt 记录由同一配额/请求 owner 提供，区分 job、实际 adapter start、重试、取消、返回用量与远端未知状态；先在显式研究 runner 记录，不增加普通用户内容遥测。
- 内存指标有样本容量限制；长批次验收由显式外部 harness 逐运行保存，不能把有界窗口误报为完整批次。
- 记录版本、构建源码身份、OS/硬件、provider/精确模型、运行时与量化、配置摘要、Prompt/数据摘要、冷暖启动及网络条件。摘要不包含密钥、完整端点、个人窗口标题或私人文本。
- 改动前后使用同一 fixture 身份、输出模式、provider 和目标；切换模型、提示词、网络策略等分别设实验，不同时改变多个变量后归因。
- 时延、可靠性与原生验收必须 fresh execution，不能用 `--resume` / quality replay 结果。冷暖态的预热次数、录音时长桶、超时、唯一 fixture 数和重复次数预先登记，不能事后丢弃较慢运行。

### 5.2 数据设计

M0b 的目标为 **120 条人工审核的真实语音**：60 条开发集、60 条正式留出集；至少 6 名来源权利已审核的说话者，新录音需参与者同意。开发/留出分属不同说话者，并隔离录音会话、模板与重复 PCM。可复用项目已审核且角色合适的数据，不强制重新录制全部开发数据；原有确定性文本 fixture 与真实音频分别编号。数量达到目标仍不自动证明正式留出，项目级准入不满足时只能称为 pilot。

每个集合按主类别各 10 条：中文日常、中英技术词、明确改口、否定/金额/日期、长句/口述列表、轻声/噪声。条件可交叉，但不能重复计入总样本。负样本分成不同输入契约：

- 声学负样本使用现有 `NonSpeechIndex`，类别限 silence / noise / music / non_speech；不进入 speech CER，但进入非语音误输出与失败统计。
- 引号内指令、代码/URL/路径、冲突操作属于有意义语音或文本行为任务：有录音时放 speech manifest，纯文字时放文本任务集。不能塞进 NonSpeechIndex，也不能为提高可用率从对应任务分母移除。

标注包括：逐字稿、必须保留事实、明确授权的改口、可接受整理结果/变体、任务类型、声学条件及来源权利。模型输出不能自动成为 gold。至少两位评审盲评；分歧由第三位裁定，保留原始判断与裁定原因。

音频、manifest、逐条文本报告和评分放在仓库外的专用目录，默认不进入 Git。采用现有 evaluator 的格式和大小限制；明确 `--run` 才可调用所选服务，不从个人历史自动补数据。

### 5.2.1 正式留出的项目级准入

复用 [public-corpus-preparation.md](public-corpus-preparation.md) 的 partition owner，不再实现另一套跨集判定。语音与 M2 文本来源、以及验收失败后替换的批次，均遵循：

1. 保留真实 case/source/speaker/session/template/PCM 身份及项目既有 dev/train/test、研究曝光和 reservation 事实。不能通过重命名、换 manifest 或换小批次清除既有暴露。
2. 开发探索使用 `purpose: existing_development`，允许如实记录未知；“可以继续探索”不等于准许正式验收。
3. 正式留出在看候选输出之前，取得现有 `project-partition-check`、`purpose: certified_lock` 的允许回执。绑定 partition owner 源码 SHA、实际 registry SHA、输入 SHA、完整 selected IDs、project ID 与 purpose，并保留未知/冲突/未注册的原始结论。
4. 新数据尚未注册或 grouping 不完整时不得宣称正式 lock。由现有 owner 的显式登记/角色流程处理；不能自动初始化、重建或替换 registry 来消除阻塞。分区通过仍不授予录音权利、人工标签或模型使用许可。
5. 已查看候选结果的留出批次保留曝光记录，后续仅作诊断/开发；新正式批次需重新通过完整项目家族检查。共享已曝光家族且无法证明隔离的数据仍不能成为新的正式留出。

M0b 的逐例瓶颈诊断只使用开发集；正式留出由独立评审完成标注，开发者不先查看其逐例基线输出再据此修 M1。M0b 可先完成开发基线与留出准备/准入；冻结候选后，基线与候选在正式留出上一起进行盲态对照，G1 签收后才解盲并记录曝光。

完整语音数据未准备好时，M2/M3/M4 可按其独立协议推进，但不得借它们的结果宣称 M1 质量已通过。

### 5.3 四层验证

| 层级 | 验证对象 | 可以证明 | 不能代替 |
| --- | --- | --- | --- |
| L1 确定性契约 | 本地准备、路由、保护、取消、状态身份 | 指定输入下的代码行为 | 真实模型质量 |
| L2 真实模型 | 固定 WAV 或固定来源文字，经实际 ASR/整理 | 该配置、数据集上的质量与服务耗时 | 麦克风、HUD、焦点与原生输入 |
| L3 原生流程 | 实际录音/受控音频输入、热键、目标、取消、恢复 | 测试环境中完整链路的行为 | 首次使用者是否理解 |
| L4 用户任务 | 新用户或目标用户完成预定义任务 | 该参与者样本的成功率和操作成本 | 普遍市场结论 |

Chatterfly 对照为可选独立实验：合法可用账号、用户处理安装/登录/授权后，以同一受控音频输入或明确披露不同采集方式进行比较。无法导入同音频时只做任务对照，不报告为严格 ASR A/B。竞品不可用不阻塞 VoiceFlow 自身基线与候选比较。

### 5.4 指标定义

| 指标 | 定义与计分 |
| --- | --- |
| 原始 ASR CER | 对逐字稿计算；使用固定规范化版本。技术标识符另做大小写/符号严格匹配，避免规范化掩盖错误 |
| 最终可用率 | 评审判定无需修改事实且可直接完成任务的输出 / 全部已启动的有效任务。服务错误、超时、保护回退后仍不可用均进入分母 |
| 关键语义错误 | 相对实际口述/来源出现新增事实或未经授权改变数字、实体、否定、条件、代码/路径、主体；分别归因 ASR、整理、模板和交付。词法保护通过不能替代人工语义判断 |
| 手改量 | 达到可接受结果所需字符编辑距离 / 冻结的主参考长度；参考变体须在看候选前审核锁定。没有可恢复输出的服务失败按需完整重写计 1，错误长文可大于 1，不从平均值中剔除。用户修过的预览不得当作模型首次可用输出 |
| stop-to-ready | 统一从 `stop_claimed_inner` 开始执行停止流程，到结果通过保护并可供既定输出动作使用；用同一单调时钟的受控记录。当前起点在音频收尾前，不能改为确认停止后再与旧值比较 |
| stop-to-confirmed-insert | 同一起点到独立核对原生目标内容；应用内部 StopToInsert 仅在 PasteConfirmed 时入时延桶，属于应用自身回读证据。外部裁判单列，不将 copied/unverified 混入该分位数 |
| 交付结果 | 已确认输入、已尝试输入、只复制、仅历史、失败、取消分别计数；复制不能算输入成功 |
| 请求与费用 | ASR 与 LLM 分开；job、实际 adapter starts、取消、重试、已返回用量及未知用量分别记录。全试验的失败/取消任务开销也进入分子；基线零用量仅报绝对增量，不算百分比 |

失败与超时不能从时延报告中静默移除。成功样本的分位数与全任务成功率、超时数同时报告；取消的任务单列，不能重标为正常成功。失败率上升时不能凭成功样本更快宣称性能改进。

## 6. M1：只修复有证据的质量问题

### 怎么改

按 M0 错误定位到单一阶段：

| 错误来源 | 优先检查的代码 | 允许的改动 |
| --- | --- | --- |
| ASR 专名/混输 | [asr.rs](../src-tauri/src/asr.rs)、[lexicon.rs](../src-tauri/src/lexicon.rs)、provider 适配器 | 已授权术语的选择/传递或格式修复；不自动更换默认模型 |
| 改口、口头语、列表 | [spoken_revision.rs](../src-tauri/src/spoken_revision.rs)、[spoken_layout.rs](../src-tauri/src/spoken_layout.rs)、[llm.rs](../src-tauri/src/llm.rs) | 修正有来源证据的局部规则或 Prompt；保留引用、否定和不确定性 |
| 整理误改/保护误拒 | [protected_span.rs](../src-tauri/src/protected_span.rs)、[text_action.rs](../src-tauri/src/text_action.rs) | 修复具体表示或授权归因问题，检查相关消费者；不全局放松保护 |
| 词典未命中或误学 | [dictionary_learn.rs](../src-tauri/src/dictionary_learn.rs)、[lexicon.rs](../src-tauri/src/lexicon.rs) | 修复实际范围、候选或替换缺陷；不重建观察循环 |

每个修复记录触发输入、根因、预期结果、对应非触发反例和生产调用路径。开发集用于调优；留出集只用于冻结候选验收。失败后保留曝光与项目家族记录，新候选只能用重新通过 5.2.1 准入的正式批次验收，不能靠换编号解除污染。

### 怎么 verify

1. 先跑相关确定性用例，确认问题经真实生产准备/保护函数重现。
2. 固定原始 ASR 文字比较整理，隔离整理收益；固定 WAV 比较 ASR，隔离识别收益。
3. 再跑完整 WAV → ASR → 整理，不用第二阶段弥补后的结果掩盖第一阶段退化。
4. 对长句、否定、代码、引用和错误回退做盲评；所有任务计入失败统计。

### G1 成功门槛

- 留出集中关键语义错误为 0；这是本测试集结果，不是全场景保证。
- 最终可用率至少 90%。
- 若基线可用率低于 95%，候选须满足预先选择的一项主收益：可用率提升至少 10 个百分点（仅当基线不高于 90% 时可选），或平均标准化手改量降低至少 20%；同时不降低可用率。基线手改量为 0 时不得算相对降幅；指标分支须提前登记，不能验收后择优。
- 基线已达到至少 95% 可用且平均标准化手改量不高于 0.02 时，可提前登记为质量保持验收，不宣称质量提升；另做主要瓶颈的性能/体验收益。未满足这些条件不得以“接近零”为理由跳过门槛。
- 不允许任何主类别多出关键错误；类别样本较少时报告逐条变化，不宣称统计显著。
- 不达标则不合入这项质量调整，或继续开发后以新留出批次复验。不能以“Prompt 看起来更好”结项。

## 7. M2：三个显式整理模板

### 7.1 用户行为与输出边界

用户在原 App 选中文字，使用现有文字操作快捷键明确说出模板要求。模板是现有 `Organize` 的有限变体，不切换默认听写模式，不执行工具。

| 模板 ID（M2a v1） | 明确指令示例 | 允许结果 | 禁止结果 |
| --- | --- | --- | --- |
| `developer_task` | “整理成开发任务”；英文“organize as a development task” | 在固定标题下保留已有原文 | 提炼或重排目标、约束、验收要求；自动指定技术栈、性能指标、工期或生成未口述的实现 |
| `work_update` | “整理成工作进展”；英文“organize as a progress report” | 在固定标题下保留已有原文 | 将计划写成完成、重排完成项/阻碍/下一步或替用户作出承诺 |
| `todo_list` | “整理成待办”；英文“organize as a to-do list” | 按来源中已有空行分段添加列表标记，保留每段原文 | 在段内拆分任务、推测负责人或截止时间，或创建系统日历事项 |

v1 只添加一个由 Rust recipe spec 定义的中/英固定标题。普通正文按来源已有的空行分段，并在每个非空段前添加固定 `- `；正文所有原始字符和空白须逐字保留。单段来源保持为单条，不拆分任务、不提炼字段、不重排完成/阻碍/下一步；含代码 literal 的正文完全原样，不加列表标记。来源中已有的标题、实体和否定仍是正文内容，不得被标题校验移除。

预览中的静态说明为“未提供的信息不会补写”；这不是模型识别了哪些字段缺失的声明。模型返回的 recipe draft 必须通过固定标题与 source-body layout proof，再通过原结果 guard，失败沿用现有错误路径而不降级为弱 guard 预览。未来的段内拆分、字段提取与分组重排均需独立契约、实现和验收。

### 7.2 怎么改

- `text_action.rs`：为 `Organize` 增加可选、封闭的 recipe 枚举。只从明确、未否定、未引用的操作指令识别；来源正文词句不参与触发。冲突或不完整的 recipe 选择拒绝；其他五类操作不能携带 recipe。通用 `Organize(None)` 保持原规划行为。
- 把 recipe 与 source、instruction、operation 一起绑定到不可变的验证证据。改动 recipe 后不能继续使用旧 plan 的验证结果。
- recipe 的版本、可用标题和正文 layout 规则由同一 Rust owner 定义。recipe 候选必须是一个精确标题行和确定性 source-body layout；标题只校验并投影一次，来源不改写。正文逐字匹配来源布局后仍运行现有 guard。
- 现有 guard 对受保护实体按出现顺序校验，但否定目前只比较识别标签的数量，不能证明否定与具体事实的归属；有序实体检查也不能证明普通语义。禁止把它描述成完整事实裁判，M2 的模型可用性和语义准确性仍由任务集盲评与人工裁判负责。
- 在单一 Rust owner 中保存内置模板语义与版本；Prompt 构建复用现有 `llm.rs` 文本操作入口。前端只保存展示文案和固定 ID，不重复实现安全规则。
- 严格 layout proof 不按 Term 值豁免。只接受 recipe 白名单的独立首行标题，不接受正文中的同名词、未知/带事实标题、source 自带标题删除或段内改写；代码来源保持字节、缩进和换行完全原样。无法证明安全时拒绝。
- 在 `lib.rs` 的实际计划构建、queue 请求、`validate_generated_result` 和预览载荷组装点贯通 recipe；`selected_action.rs` 继续负责相应会话/确认交付。Rust 预览模型、载荷和 TS 类型同步携带有限 recipe 标识/版本，沿用一次性 transaction、代际、取消与来源复核。
- `SelectedPreviewDialog.tsx` 显示“开发任务整理 · 选中文字”等实际元数据，保留编辑、复制、确认、取消。v1 不新增复杂的预览内二次改模板/重跑状态机。
- 在现有 `SelectedLesson`、完成引导及相关设置入口加入简短的“选来源 → 说指令 → 核对结果”示例。预设前后对照明确标为示例，不冒充真实模型输出。

## 10. X1：停顿预处理的条件实验

### 10.1 先解决准入，再写生产接线

Chatterfly 的静态路径只证明这个设计存在。VoiceFlow 当前的 ASR 结果语义、授权和成本必须独立成立。

先做外部 fixture 驱动的研究实验。生产候选仅接受已证明可独立使用的 provider 确认片段或已完成的全覆盖 ASR 结果；“界面看起来稳定”、provisional token、未完成 batch 和任意 `is_final` 名称都不足以准入。现有 Soniox provisional 不进入 cleanup 的约定不变；没有合格文本来源就不接入该 provider。

文本可用与请求获准是两个条件。每次 speculative dispatch **以及每次实际重试开始之前**，由生产调用方复用当前 session 模式、准备稿/intent、snippet 决策和 `cleanup_route_for_resolved_scene`，复核 Off/LocalOnly、skip-cleanup、严格离线、目标/场景 hard veto、实际 provider 能力、当前上下文/样例 grants。有限文本操作、翻译、snippet 等尚未证明兼容的路径不准入 v1。不能仅因最终结果会校验或丢弃，就给这些路径提前发送文字。

如果停顿时不能证明当前请求本身合格，保持不请求；先做本地 shadow/受控事件重放，记录无法准入的原因。重放只能使用当时已经到达的文本与事件，不能偷看完整录音、最终转写或 gold 来决定触发。最终指纹只用于事后判定可复用性。

### 10.2 合格后怎么改

- 在现有录音/ASR/整理会话 owner 中设置可取消的单个 speculative job，避免第二套独立会话管理器。
- `prefetch_asr.rs` 继续拥有 ASR 覆盖与身份；`llm.rs` 负责 Prompt、传输和 adapter 级检查。`lib.rs` 的生产调用方保留请求准入、当前权限投影、授权重验、最终完整准备稿与 `FinalizationContext` 的编排；helper 只能管理候选身份/取消，不能直接调 adapter 绕过这些步骤。
- `queue.rs` 增加有限的 speculative 请求目的/通知策略（例如 `SpeculativeLlm`，名字以最终实现为准），共享现有 LLM 配额、并发与取消 owner。不能直接用前台 `Llm` 通知分支：录音中遇到 429/退避/重试恢复，不得发布前台 dictation/quota 的 processing、失败或完成事件，也不得冒用 WritingPreview 的用户状态。
- 研究起点：首次符合条件的停顿持续 700ms 才尝试；单次录音最多 1 个**本地**未结束的 speculative job，speculative **实际 adapter starts 合计最多 2 次**。每次重试、已启动后被取消的调用均消耗同一预算，排队但未启动的取消单列。预算在实际调用前原子扣减，queue 自带的 429/transient 重试不能另增预算。参数是待测起点，不是已证明最优值。
- 最终正常请求继续由既有 owner 和重试策略负责，另行计数；同时记录本次录音的所有 speculative/最终请求总量。本地 job 结束不证明远端计算已停止，也不能据此宣称远端仅有一个并发请求。
- 指纹至少包含录音/处理代际、已确认转写与准备稿摘要、模型/服务配置版本、Prompt/模板版本、语气、授权上下文与词典版本。摘要不能进入普通用户日志暴露正文。
- 新语音、文本修订、目标/上下文变化、权限撤销、配置变更、取消均使候选失效。取消只表示本地停止使用结果；远端是否停止计算/计费另记未知。
- 只有最终完整来源与所有有效输入指纹一致时，才可复用候选；仍通过当前授权投影重验、完整准备稿的 revision/list proof/晋升词条保护及现有交付。adapter 检查通过不替代最终保护。否则走普通最终请求，不能拼接猜测文本。
- 预处理输出留在当前会话内存，保持原有大小上限；不写目标、剪贴板、History、词典或新的磁盘缓存。
- 初始仅研究构建显式启用。生产暴露开关前先定义兼容 provider、提前请求的说明、请求预算及关闭后的清理语义；默认保持关闭。

### 10.3 怎么 verify

- L1：反复停顿、改口、继续说、末字晚到、两次录音交错、权限/配置变化、取消响应迟到、超时、429、丢包和结果保护失败。断言失效候选 0 次用于最终输出。
- L1 发送准入：Off、LocalOnly、skip-cleanup、严格离线、snippet、有限文本操作、未获准上下文/样例等路径的 speculative adapter starts 为 0；每次重试前再检查，而非最后才弃结果。
- L1 队列副作用：录音中 429、退避和恢复保持 recording HUD；无前台处理/失败/完成事件。配额仍真实扣减，取消不清除其他任务的配额，speculative starts 总数不超过 2。
- L2：同音频同配置对比候选命中、浪费请求、最终质量和用量覆盖；无 provider 使用权限时仅运行本地模拟，不能宣称服务收益。
- L3：每个拟支持的 provider/路径，3–10 秒与 10–30 秒两个时长桶，基线与候选**每个版本每桶**至少 100 次暖态测量，至少 10 个不同 fixture，按块随机交错；冷态每版本每桶至少 20 次。分开报告唯一音频、说话者、重复次数与冷暖态，不能把重复播放当新增说话者证据。另用相同、预先固定的取消/失败任务安排核算全部成本，覆盖真实取消和 App 切换。
- 真实麦克风与 fixture 注入分别标注；后者不能替代采集端验证。网络故障用任务专属注入或受控代理，不能修改全机网络或捕获个人流量。

### G5 进入产品的门槛

- G0 全部通过；冻结质量任务上关键语义错误为 0，可用率不低于基线。
- 主目标桶 stop-to-ready P50 同时减少至少 20% 和 200ms；P95 不比基线增加超过 5%。两个时长桶分别报告，不能用平均值遮掩退化。
- 全任务失败率不增加；按预先登记的容差与逐条错误核对，不能移除失败后计算收益。
- 预算与成本：对预先固定的整个试验，分子包含已完成、失败、超时、取消任务发生的所有 speculative、最终请求和重试；同时报告除以全部启动任务数、除以完成任务数的两套平均请求/费用，不能剔除取消任务成本。所支持范围内两种口径均不比非零基线增加超过 20%。
- 基线请求/费用为 0 的路径不得计算百分比：若其生产策略禁止整理，候选额外请求必须为 0；其他获准路径需在实验前登记绝对预算。返回用量、经核实的价格来源/时间及取消请求开销不足以支持费用核算时保持研究状态，不能仅凭 ASR 用量或“已取消”宣称费用达标。
- 从生产 owner 接受本地取消到候选标记不可复用的 P95 不超过 100ms；这不证明远端终止。失效/旧代际候选进入交付为 0；物理按键到 owner 的延迟另报。
- 不达标时移除生产接线或保留关闭的研究 helper，并记录不采用原因。候选命中率只作解释指标，不作为用户收益替代品。

- 原生验证：目标 App 焦点不丢，快捷键与 Esc 可用，主胶囊不跳位；隐藏与 reduced motion 不保留持续动画。
- 对可稳定出字的受控网络任务，使用 3–10 秒与 10–30 秒两个时长桶，候选每桶至少 100 次；预先登记唯一 fixture、重复及合并/丢弃更新计数。收到 provider partial 到 UI 更新回执的本地 P95 不超过 150ms。用同一 Rust 单调时钟关联 partial 接收与对应 UI commit/帧边界回执，回程包含 IPC，作为保守本地指标；不能直接相减 Rust Instant 与 JS performance.now，也不能将回执冒称像素已被人看到。像素布局另做渲染检查，provider 到首字时间单独报告。
- 基线/候选每版本每桶至少 100 次比较 stop-to-ready 与资源开销。基线没有草稿显示，其 partial-to-UI 指标应记“不适用”，不能记 0ms，也不能要求没有显示路径的基线提供 UI 回执。
- 同一环境下 stop-to-ready P95 回归不超过 5%；记录 CPU/内存，完成/取消后无持续增长或残留订阅，不作未经测量的资源收益声明。
- 8 名目标用户中至少 6 人认为长句/指令时更容易确认“系统听到了什么”，至少 7 人理解草稿会变化；同时记录干扰与偏好关闭的反馈。
- 代码通过但用户收益不足时保持关闭；不得把“出现文字”作为唯一成功定义。

## 12. 共用的交付、隐私与故障门槛 G0

以下是触及相应链路的候选交付否决项。每项改动验证其实际影响与公共负控制；完整产品候选再覆盖整张原生矩阵，不要求纯文案修改重复所有 provider/录音实验。测试结果只适用于列出的环境与样本，不能写成绝对安全保证。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 目标 App/字段/选区改变 | 不覆盖新内容；按已确认的复制/历史状态提示 |
| 双击确认、迟到成功、旧会话响应 | 不重复写入、不复活已取消任务 |
| 安全输入、权限拒绝或撤销 | 保护保持，无法确认则明确失败/降级 |
| 剪贴板被其他应用改动 | 尊重现有所有权规则，不盲目恢复或覆盖 |
| ASR/LLM 错误、超时、429、断网 | 不假成功；有已确认保存的内容才提示可恢复 |
| 选中文本/模板取消 | 不存入普通 History 或学习；原有 ASR 失败音频恢复政策保持 |
| 严格离线、未批准上下文 | 无新增云请求、截图、文字发送或样例外传 |
| 打开教程、详情、折叠面板 | 不改变授权、保存状态或触发模型 |
| 热键失败、设备切换、重启 | 无错误 readiness、无会话串扰，恢复按当前配置运行 |

故障矩阵至少覆盖 TextEdit、浏览器原生编辑框、网页富文本编辑器和一个常用聊天/开发 App。各类别至少 10 次成功路径及适用的失配/取消路径；终端与受保护字段单独验证保守行为。第三方 App 无法可靠回读时，将结果标为“已尝试/不可核验”，不归入确认成功率。

原生交付至少保留独立的受控目标内容核对；不能只用应用自己的“已粘贴”回执证明成功。涉及剪贴板与窗口内容的核对只针对明确准备的测试 fixture。
