# VoiceFlow 数据与隐私说明

History 数据库启用 SQLite `secure_delete`。较旧 schema 首次迁移时，使用 `VACUUM INTO` 在数据目录内新建的私有 `0700` 临时目录生成一致备份；通过完整性检查并限制为 `0600` 后，才以不覆盖已有路径的原子方式发布。删除 History 会等待其 spool owner 释放路径，在删除数据库记录前先将关联 manifest 标记为完成，避免启动恢复重新生成已删除记录；若 spool 删除无法确认，会返回错误。清空 History 后会尽力 VACUUM 回收数据库页，失败会报告给调用方。

## 数据流

没有携带共享 cleanup plan 的遗留 Groq Cleanup 路径，仅在候选因遗漏编号列表前的准备稿前言而触发布局拒绝时，才尝试保守恢复；候选和重建文字仍在本次请求内存中，并重新经过原有完整保护检查。普通短录音、长录音和 History 音频重试使用共享 plan，不追加该 Groq reminder；StructureSafe 候选不会通过 legacy preamble recovery 复活。其它非 StructureSafe 路径仍只在原有证明条件下使用其既定恢复规则。成功听写只按既有 History 规则保存最终文字，不另存该候选。默认忽略的 live fixture 仅在显式运行时向 Groq 20B 发送两条固定 cleanup 样例；密钥经限时 stdin 传入、不读 Keychain。运行前须设置 `VOICEFLOW_GROQ_PREAMBLE_LIVE_REPORT` 指向仓库外的私有目录中新文件；fixture 使用 `create_new` 创建 `0600` 报告，内容含固定样例、解析后的候选和最终结果 / 阶段 / 耗时，不含密钥、认证头或设置，报告不会自动上传。

「语气」中的试跑仅在用户点击按钮时运行。使用手动输入的样例文字、当前 / 已保存 Prompt、场景与语言配置，并复用本机准备、手动词典提示、整理路由和事实保护规则；不会捕获当前 App、屏幕、剪贴板或 History，不附加 App 风格示例、自动上下文或语音片段。允许调用模型时只请求已配置的整理服务；AI Off、保守场景和严格离线约束仍生效。草稿比较最多顺序执行两次请求，取消、关闭试跑或编辑样例 / Prompt 会使迟到结果失效；关闭后的样例和结果不保存。配置变更后的结果不会显示，试跑最长 90 秒。它不写入 History、词典学习、日志或其他 App。

独立翻译快捷键默认未设置。它只为自己启动的录音固定目标语言，将完整本机准备稿作为正文交给明确的翻译操作，不需要额外口述翻译指令；正文里的指令或语言名称不改变固定目标。沿用普通听写的音频、授权、保留和目标核对规则，不修改全局输出模式，也不赋予额外的截图或文字读取权限。开始前检查当前场景整理路由和凭据；严格离线模式继续阻止云端整理。

首次引导的试用使用原生会话租约。录音开始时固定试用 ID、配置版本和触发来源，短录音、长录音及选中文本试用仅返回应用内预览；它们不根据当前页面或可变开关改成外部粘贴、剪贴板写入或普通成功 History。返回、关闭或替换试用会撤销租约并使用原有取消流程，旧结果不能推进新试用。选中文本的试用来源在接受操作时固定，旧操作不能读取新试用选区或回落到外部窗口检测；合成试用样例只以本次租约、操作版本和本机指纹复核。状态、错误和结果使用原操作快照，试用回执只发送给主引导窗口，通用 HUD 状态不生成试用事实。原生热键回调可被合成事件触发，因此只标记 `native_hotkey`，不据此宣称实体按键已验证。配置版本由后端设置 owner 生成；设备、语言、模型、权限快照或快捷键变化使对应旧试用事实失效。失败录音的现有恢复策略仍生效，试用不会生成训练标签。

辅助功能与看屏幕的操作提示由对应的明确动作开启。macOS 原生小窗只拖动当前运行 `.app` 的规范文件 URL，并显示实际 App 图标；开发进程没有有效 bundle 时显示无法拖 App 的说明。窗口可移动、调整大小、关闭，提供系统设置、Finder 和重新检测路径。拖拽完成或打开系统设置不代表已授权，实际辅助功能 / 屏幕权限由现有 native owner 读回。提示只在唯一系统设置窗口的现有几何元数据可确认且屏幕有空间时相邻摆放，否则保持独立可移动说明；不通过截图或未取得的辅助功能权限读取系统控件。普通听写不会请求屏幕权限。

HUD 外观默认使用 `classic`。用户可显式选择 macOS 26 或更新版本上的 `liquid_glass`；系统开启减少透明度、系统版本不支持或原生安装失败时，HUD 继续使用 classic。设置页只在后端确认所选外观发生回退或未能应用时内联报告原因，不显示常规保存和有效外观状态。Settings 中的玻璃预览只使用本地合成样例背景，不读取活动桌面或窗口像素；真实 HUD 的 Glass 由 AppKit 合成在现有 HUD WebView 后方。VoiceFlow 不读取、保存或发送材质后面的像素，不新增屏幕录制或辅助功能权限。原生材质在暖面板空闲、粘贴已分发及终态隐藏时收起；WebView 保持原有交互与恢复按钮所有权。

普通听写的粘贴 owner 会在本机短暂读取可用的焦点字段 value 与 UTF-16 选区范围，用于核对预期插入；发送 `Cmd+V` 前会复核已知值。macOS 系统安全输入开启时，owner PID 会与已捕获的目标 PID 比较：目标 App 持有时拒绝自动粘贴；其他或未知 owner 时不发送快捷键并进入现有剪贴板 / History 恢复流程。AX secure text field 检查保持独立。发生字段变化或已知值变得不可读时也不发送快捷键。诊断先描述已观察到的原因，不提前承诺复制或保存；终态只有在 clipboard ownership 已证明时才报告复制，只有 History 写入成功才报告已保存，写入错误会明确显示。若系统 secure input 持续开启或由另一 App 持有，自动粘贴会在此期间退回复制流程。AX 原先无法提供的字段继续保持 unknown。这个校验不会把字段文字写入 History、诊断或 provider 请求。

普通听写完成状态在当前进程内只保留有界、无正文的随机进程 / 事务身份、交付结果类别和 writer 准入 / 关闭事实；它不会写入 History、持久日志或网络请求，也不包含 transcript、目标字段或剪贴板正文。Island 胶囊隐藏时，这条人类可读状态仍在其隐藏子树之外。普通听写在原生快捷键发送成功后按 session generation 收起 HUD；发送前的 dispatch gate 会先记录可能已发送的事实，并与 watchdog 共用 manager 锁。若 watchdog 先取得该锁，旧 paste owner 的 gate 会拒绝后续快捷键；若 owner 已越过 gate，则 global / local watchdog 只取消并等待原 writer 结算，不弹前台错误或音频恢复提示，也不重发。正常路径中 AX 读回仍由原 paste owner 在后台完成，Processing phase 与 live operation lease 在读回 / 剪贴板 ownership 结算前保持占用；watchdog 结束处理 phase 后，live operation lease 仍保留到已准入 writer 关闭。读回未确认或 owner 回执丢失时，结果仍写入原 History 与无正文诊断，不触发 HUD 复制恢复；paste owner 线程明确启动失败时，结果只进入现有 History 复制恢复路径，不新写剪贴板；确定未发送且原 clipboard ownership 规则允许恢复时，才显示相应复制路径。源码把实际后端快照写入保留的原生 AX 元素标识，并用人类可读 label / value 描述交付结果；status element 也显式绑定到所属 NSWindow 的 accessibilityWindow 与 accessibilityTopLevelUIElement。打包应用中的实际 AX 关联、label / value 公开与 VoiceOver 行为仍待独立验证。原生值变化通知目前也未接入，避免未经 VoiceOver 双播检查就同时启用两个播报路径。该状态不会证明剪贴板恢复、最终读回或下一次录音 readiness。

音频评测 CLI 与日常录音分开。默认只校验外部 WAV 清单；只有显式 `--run`、审核过的来源说明、指定模型和显式环境 / 文件凭据齐备时才调用所选服务。它不取用麦克风或 History，也不自动使用 Keychain / 历史 sidecar 密钥。清单、WAV 和报告必须在仓库外，报告包含参考文本、ASR 转录和整理结果，须按样本的数据要求管理；报告不包含 API Key，不复制音频。

VoiceFlow 的会话录音只在用户主动触发 dictation 后开始。默认按需打开麦克风；开发构建中明确开启可选常开麦克风后，空闲输入流持续打开，但样本直接丢弃、不保存、不发送。发行构建忽略已保存的开启值，并拒绝该设置字段更新。若麦克风权限仍处于未决定状态，首次触发会请求 macOS 显示系统授权提示；只有用户允许后才开始采集。拒绝授权或权限已关闭时，录音不会启动，可从「系统权限」页前往 macOS 隐私设置。默认 ASR 仍是 Groq `whisper-large-v3-turbo`，不会因增加预设而改变已有选择。用户也可选择 OpenAI `gpt-transcribe`、Deepgram、SiliconFlow、Fireworks、本机 Whisper HTTP、Mistral、Soniox、AssemblyAI Dictation / raw Sync、DashScope Qwen Audio 3.1 Message、On Device 或自定义 endpoint；已有 provider、model 与 custom endpoint 配置会保留。SiliconFlow 仍以 `FunAudioLLM/SenseVoiceSmall` 为默认 ASR model，并增加可选 `Qwen/Qwen3-ASR-1.7B`。新增的独立 provider ID 是 `fireworks`（`whisper-v3-turbo`，base host `https://audio-turbo.api.fireworks.ai`）、`mistral`（`voxtral-mini-2602`，base host `https://api.mistral.ai`）、`soniox`（实时流式专用 `stt-rt-v5`，WebSocket `wss://stt-rt.soniox.com/transcribe-websocket`）、`assemblyai`（Universal-3.5 Pro）和 `dashscope`（`qwen-audio-3.1-asr-flash-message`）。Fireworks 服务可用性尚未核实；Qwen 预设的账户和地区可用性也尚未核实。Soniox 的真实麦克风连接尚未验证；本阶段未验证 AssemblyAI / DashScope 账号与服务可用性。Deepgram 预设不启用 `multi`，不据此宣称中文或中英混合支持。

macOS 明确报告屏幕合盖且 CoreAudio 将本次所选输入设备标识为有稳定 UID 的内置传输设备时，主动开始的录音和麦克风自检会在打开音频流前停止，并提示用户打开屏幕或选择外接麦克风。常开输入流的自动预热若遇到同一状态，只记入现有日志，不弹出提示；之后用户主动开始录音或自检时才会看到启动错误。已配置的合盖替代输入先应用；其设备仍按 CoreAudio UID 和传输类型判断。身份清单不完整、有歧义或选择在读取期间改变时不会仅凭设备名称拒绝输入。这个检查在每次主动打开输入流前进行，不监视已打开流期间的合盖变化。

可选集成 provider `assemblyai` 提供 Universal-3.5 Pro 的 Dictation / raw Sync 双路径；`dashscope` 只提供 Qwen Audio 3.1 ASR Flash Message 原始 ASR。DashScope region 在设置和引导页显式选择并保存为 Beijing / Singapore 的 HTTPS origin，再映射到官方 WSS host；不使用 Workspace ID。保存 key 只代表凭据已配置，真实账号 / 地区可用性与服务质量未在本阶段验证。默认 Groq `whisper-large-v3-turbo` 和 cleanup `openai/gpt-oss-20b` 不变。

On Device 当前提供五款可供新选择和用户主动下载的本机 ASR：`qwen3-asr-0.6b`、`qwen3-asr-1.7b`、`parakeet-tdt-0.6b-v3-8bit`、`firered-asr2-aed-mlx` 和 `fun-asr-nano-2512-mlx`。后端只在固定清单及对应可执行 sidecar route 存在时设置 `download_available`；该字段独立于平台支持、文件状态、运行时握手和 `inference_ready`。下载操作另按模型固定 reserve 与 `hw.memsize` 的 80% cap 做静态容量检查；容量不足或内存未知时禁用下载，且命令在传输前复核。此检查不使用瞬时内存压力或当前 sidecar footprint；实际冷加载仍执行动态准入。这五款模型尚未完成真实模型推理或转写质量评测；route 编译确认不代表真实模型推理或转写质量评测。Qwen 0.6B / 1.7B 支持自动检测或固定中文 / English；Parakeet 和 FireRed 仅使用自动语言策略，运行时不返回检测语言。Fun-ASR Nano 接受 auto / zh / en prompt，但转录语言保持 nil，因为 SDK 只回显 prompt。Cohere Transcribe 2B 只保留当前已保存选择和现有文件管理，不提供新下载或选择。1.7B 与 Cohere 转换产物许可仍未审查；上游 Apache-2.0 声明不确定转换器输入、转换器许可或转换产物许可，详见 [`ThirdPartyLicenses/Models/`](../ThirdPartyLicenses/Models/source-manifest.json)。模型文件就绪仅表示文件校验状态，不代表转写质量已验证。运行要求 Apple Silicon 与 macOS 14 或更新版本。Cohere 模型必须选择中文或 English 固定语言；自动语言检测不可用。旧 `sensevoice-small` 配置与本机文件继续保留（不再提供下载），但该文件路径没有 MLX 推理支持，即使文件已就绪也不能通过 MLX 推理探测或启动 MLX 转写。设置页将文件校验状态、sidecar 能力握手、当前模型加载中和已加载模型分别展示；加载状态绑定具体模型。握手只确认 sidecar 能力，不代表所选模型已加载或一次实际转写成功。用户可取消当前模型加载；取消会停止这次加载，不更改已保存的 provider / model 选择，也不删除下载文件。正式发行构建只从 VoiceFlow `.app` 的规范 `Contents/Resources/voiceflow-mlx-sidecar` 路径启动 ASR 与本机 cleanup helper，不读取 `VOICEFLOW_MLX_SIDECAR_PATH`；该覆盖路径只用于开发及显式 evaluation / research-harness 构建。

本机 MLX ASR 首次校验、证明缺失或任一绑定身份变化时，会完整散列固定清单中的模型文件。后续只有模型 ID、repository、revision、固定清单、已安装 marker 的原始字节，以及模型根目录、模型目录和每个文件的设备 / inode / 大小 / mtime / ctime / 权限 / 所有者 / 链接等身份全部匹配时，才会使用耐久 proof 跳过大文件散列；proof 保存在模型目录之外的 app-private 位置，目录和文件权限为 0700 / 0600。proof 读取或校验失败会回到完整散列；proof 写入失败不会使已完整验证的本次加载失败。研究来源准入仍完整散列文件并保留已打开描述符。

听写期间取消会让 Rust runtime 的独立请求 owner 持有 sidecar 会话和私有 WAV，直到原转写终态与匹配的取消确认都被读取，或取消宽限期届满并观察到子进程退出。正常结果也只有在原请求身份匹配、状态为 `completed`、平台支持、无错误或 foreign payload、加载模型身份匹配且完整转录通过覆盖、完成度、token 预算和非空校验后，owner 才释放 WAV 和会话 gate；调用方丢弃期间的响应不会绕过这些检查。配对响应缺失、顺序或身份不符时会退役该子进程；确认其退出前不会释放 WAV 或允许会话替换。运行时关闭及模型加载 future 被丢弃时都会保留活动 PID，直到 Child 退出被实际观察。退出 App 时若无法确认 MLX 子进程已退出，首次退出请求会保留 App 与上述所有权；用户再次退出时，App 会再次终止仍持有的本机 ASR sidecar、删除本进程保留的私有 WAV 并强制退出。ASR Swift sidecar 使用固定 `mlx-audio-swift` 上游 revision 的哈希约束 source overlay：patch 覆盖四个 SDK 文件，并加入固定上游 revision 的三个 Fun-ASR-Nano 源文件。协议 dispatcher 保留并取消同一个 detached worker Task，模型 owner 在自己的串行执行器里运行实际转写；SDK 的 Qwen / Cohere batch、分块、预处理和评估边界读取可跨队列查询的取消 latch，Fun-ASR-Nano generator 在 chunk、prefill 和 token 检查点读取 `Task.isCancelled`。Parakeet 与 FireRed SDK 调用是同步的，取消在调用返回后的 sidecar 检查点生效；其他同步 MLX 原生调用本身也不可被 Swift 中途抢占。worker 返回 DTO 后，sidecar 同步实际使用的 GPU 与 CPU stock streams，再输出原请求终态及身份绑定的 cancel 确认。有效配对保留已加载模型。fake-worker 和合成 SDK 测试不代表真实模型延迟、Metal 取消时延或 App 端到端行为。

“严格离线模式”允许 On Device ASR 及本机 cleanup；所有 HTTP ASR 路由与探测会被阻止，云端 cleanup、视觉、History 重试、cascade / prefetch 和云端文字操作也会被阻止或取消。cleanup 可使用经验证的 loopback Ollama `qwen3.5:4b`，或 VoiceFlow 管理的 `on_device_mlx`。VoiceFlow MLX 提供五款本机整理选择：Qwen3.5 2B / 4B、Gemma 4 E4B IT、Ministral 3 3B Instruct，以及原有 Qwen3.8 27B。已安装的旧版 MLX / GGUF 文件仍可管理；当前已保存的旧路线可继续使用，其他旧模型不提供新的下载或选择，也不会自动更改配置。MLX 要求 Apple Silicon 与 macOS 14 或更新版本；GGUF 的已保存路线使用随包 llama.cpp，需要 Apple Silicon 与 macOS 13.3 或更新版本，并按设备内存预算检查兼容性。平台不支持或状态未知时不会开始模型下载或打开导入文件夹。不可用时走本地规则或关闭整理，不自动切换到 Ollama 或云端。ASR 与 cleanup 模型下载都由用户主动发起，需要网络，且与严格离线推理分开。MLX cleanup sidecar 输出前按完整 UTF-8 JSON 行（含换行）检查 65,536-byte 上限（最多 65,535-byte JSON payload 加换行）；超限会保留 request/session 身份并返回 `response_too_large` 结构化错误，不截断清理文本。

`on_device_mlx` 使用随 VoiceFlow 打包的 Swift/MLX cleanup 子进程与 JSONL 通信，不依赖 LM Studio 应用 / CLI 或 Python。可供新下载和选择的固定 MLX 清单是 Qwen3.5 2B、Qwen3.5 4B、Gemma 4 E4B IT、Ministral 3 3B Instruct 和原有 Qwen3.8 27B；原有 27B 固定为 `lmstudio-community/Qwen3.8-27B-MLX-6bit` revision `05f38c1f39e2f39619653616fe8e96a5d676358e`，支持用户主动下载或导入匹配清单的目录，APFS clone 建立独立管理副本。四款新增 MLX 模型由固定 revision、文件清单和 SHA-256 管理，不开放文件夹导入。`download_available` 与 `release_qualified` 在目录元数据中分别记录；设置页不显示质量评测结论。文件校验只确认文件与固定清单一致，不代表模型已通过完整整理质量评测。已安装的其他 MLX / GGUF 文件仍可查看和删除；当前已保存的旧路线保留，未列入新清单的模型不会提供新的下载或选择。所有已安装模型都仅从本机已校验的管理副本推理；模型下载需要用户主动联网，模型和整理文本不会上传。取消会保留已验证的 partial，卸载后删除只移除管理副本。首次加载与驻留状态分开展示，均不证明模型质量；普通听写和 History cleanup 共用现有 provider 路由与最终保护检查。

在用户已完成引导、启用 cleanup 且固定本机模型已就绪时，应用启动后会按现有 cleanup 路由最多排队两个有界的合成 warmup。普通观察到的 Code 场景仍关闭隐式 live cleanup，因此可执行 Code History/Reclean；若仍有空位且 General implicit route 符合当前本机策略，应用会加入 General implicit warmup。预热只使用生产 prompt builder 生成的固定合成 transcript 和应用配置，不读取 History、当前 ASR 稿、窗口内容或选区，也不写入剪贴板、History 或词典学习。缓存只匹配精确的 prompt token 前缀；配置变化会使键不同，实时 transcript、来源文本、选区和窗口内容不会进入快照。持久化缓存继续使用原有 512-token 对齐路径；若不符合该路径，实际 prompt 与两条空 user-prefix 的 system-only 探针共享的 128–511 token 前缀可保留为仅内存 resident，不读取、恢复或改写 durable snapshot，并沿用同一 state 大小上限和最多两个 resident。无法证明安全边界的请求仍按原样计算。前台本机 cleanup demand 会贯穿请求生命周期；它在模型加载时只延迟后续 warmup eval，在 eval 已派发时等待同一请求的 terminal 与匹配 cancel acknowledgement 后复用 child。取消步骤不计作 warmup 完成；既有设置、模型和退出失效仍有效。此行为不改变真实 cleanup 请求，也不保证所有场景的首次请求命中缓存或达到固定延迟。

### 已保存凭据的本次会话读取

启动时无法读取 Keychain 项会作为「暂时不可读取」保留，与确认没有匹配项分开显示；读取失败本身不证明凭据已删除，也不会清空保存的 endpoint、路由或其他设置。设置视图仅接收是否有本次会话可用凭据、Keychain 读取状态和现有掩码提示，不接收完整 API Key。普通偏好保存不要求 Keychain 可读，也不会因此重写凭据。

用户可在前台「模型配置」→「API Key」页面中主动请求本次重新读取。Custom 读取只在当前已保存的 Custom ASR 或启用的 Custom cleanup 路由上开放，并绑定当前 provider、路由用途、设置代次与固定解析 origin。它先查询 `provider_custom`；只有该用途仍使用 Custom、且该用途各自保存的 ASR / cleanup URL 能证明同一 origin 时，才会查询对应 legacy 项；缺少可核实的来源 URL 或 origin 不同就跳过该项。这个严格范围只描述前台重新读取；启动时既有凭据恢复行为保持独立。未使用 Custom 的用途不会被读取为别的用途的凭据。读取不保存设置、不写或删除 Keychain 项、不改 ACL，也不请求 provider；成功只将已存在的凭据放入当前进程内存，并不验证服务连接或模型。采用的值只在捕获的 origin 和活动用途仍匹配时可用；origin 或用途变化会清除该值并禁止它回退到其他 legacy 项。离开「API Key」页面、窗口失焦、听写开始或其他占用操作 lease 的操作开始都会不可逆地取消待处理读取，即使窗口之后重新聚焦、操作返回 Idle，迟到结果也不会被采用。Keychain 是否显示系统授权提示由 macOS 决定；VoiceFlow 只在用户主动点击后发起这次读取。

Soniox 只出现在 ASR 选择中。开始听写时先建立非阻塞、有界音频队列，再于后台建立 WebSocket；麦克风采集不等待网络握手。队列溢出会标记实时流不完整，完整本机录音仍保留用于同 provider 恢复。保存设置或凭据只把 API Key 放入 macOS Keychain，并显示为已配置；保存本身不连接服务。Soniox 在设置界面没有连接测试，只有开始听写时才建立实时连接；其他支持探测的服务可由用户在服务配置或 API Key 页面手动测试。VoiceFlow 按保存的识别语言发送候选语言提示：自动模式提示中文与 English，固定模式提示所选语言；这些提示不限制识别。当前 Soniox 路径不发送自定义上下文或术语。临时 token 保留在当前录音会话，不进入 cleanup、目标 App、剪贴板、History 或词典学习；只有服务端完成后得到的最终 transcript 才进入现有 raw / final 处理流程。若流连接、音频覆盖或 finalization 失败，VoiceFlow 取消这次流并用本机保留的完整、裁剪前录音按近实时节奏向同一 Soniox WebSocket 重放一次；HUD 会显示完整录音正在重转写，不会拼接未确认的 partial，也不会跨 provider 静默回退。重放会再处理完整录音，因此可能产生第二次整段费用。Soniox 按完整实时流时长计费，包含静音；诊断中的 session 墙钟时长和发送音频秒数不是 provider 账单用量。实际价格以 [Soniox 定价页](https://soniox.com/pricing) 和账户合同为准。该服务的 [WebSocket 接口说明](https://soniox.com/docs/api-reference/stt/websocket-api)列出了实时协议与模型能力。

### AssemblyAI Dictation 与 raw Sync

可选 ASR provider `assemblyai` 固定使用 Universal-3.5 Pro。对于总音频不超过 120 秒、且当前允许 AI 整理的录音，VoiceFlow 使用 `POST https://dictation.assemblyai.com/v1/transcribe/live`。请求以原始 API key 放在 `Authorization` header；multipart 的第一个 part 是 `application/json` 配置，随后是 `audio/wav` WAV 音频。该 endpoint 每次最多 120 秒，且即使省略或置空 `llm_instruction` 也会执行默认改写；没有文档支持的 `cleanup=false` 参数。

Dictation 响应中的 `text` 是独立 ASR 原稿，`llm_response` 只是 provider 整理候选，`llm_error` 表示候选整理失败。VoiceFlow 将候选作为候选而非原稿，先与 Phase 2 本地准备稿及授权信息对齐，再经过最终 protected-span guard；只有 guard 接受后才使用候选，并跳过第二次 LLM 请求。候选缺失、为空或带有 `llm_error` 时保留 `text`；若当前场景和离线策略允许，且共同整理路由已配置并可用，就对本地准备稿执行一次共同 cleanup，否则使用本地规则回退。需要密钥的云服务必须有可用凭据；On Device MLX、VoiceFlow llama.cpp 和 loopback Ollama 可使用无密钥本机路由。若候选被最终保护检查拒绝，则保留受保护的原稿 / 本地回退，不再发第二次模型请求。HTTP 200 本身不代表整理成功。

AI Off、本地-only 场景、翻译输出模式或全录音超过 120 秒时，VoiceFlow 改用同一 AssemblyAI provider 的 raw Sync：`POST https://sync.assemblyai.com/v1/transcribe`，使用同一把 Keychain key 的原始 `Authorization` header 和 `X-AAI-Model: universal-3-5-pro`。翻译在 raw ASR 后通过当前场景和离线策略允许的共同整理路由处理完整准备稿，并沿用最终保护规则；需要密钥的云端路由必须有可用凭据，本机 On Device MLX、VoiceFlow llama.cpp 或 loopback Ollama 可免 key。配置在 WAV part 前发送；每个请求最多 120 秒。Dictation 与 Sync 都始终显式发送 `language_codes`：识别语言为 auto 时发送 `['zh','en']`，固定中文发送 `['zh']`，固定 English 发送 `['en']`。这是中英预期语言列表，不是未限定的服务端自动检测；API 文档列出 32 个语言代码，而产品设置仍只有 auto / 中文 / English。Sync 只使用专用 `keyterms_prompt` 发送有界术语，最多 100 项、总长 8000 字符；不发送会使 `language_codes` 被忽略的通用 `prompt`。

长录音由有界重叠 chunk 完整覆盖，每段走 raw Sync；全稿合并后最多运行一次共同 cleanup，不逐段改写再拼接。长录音的模型整理需要当前场景和离线策略允许、且已配置的共同 cleanup 路由可用；需要密钥的云路由若凭据缺失或服务不可用，应用保留 raw / 本地准备稿并使用本地规则回退，本机 On Device MLX、VoiceFlow llama.cpp 或 loopback Ollama 可免 key。关闭 cleanup 时只保留本地准备稿。短录音的 fused Dictation 候选不依赖共同 cleanup 密钥；候选缺失、为空或带有 `llm_error` 时，仅当共同 cleanup 路由满足场景、离线和凭据条件时才会再请求，否则保留原稿并使用本地规则回退。若候选被最终保护检查拒绝，则保留受保护原稿 / 本地回退，不再请求第二个模型。请求取消、严格离线切换或设置版本变化会阻止迟到的云端结果进入 History 或交付；History 重试与引擎探测也必须遵守同一离线与取消策略。设置保存只做本机结构、密钥与地址绑定、模型文件及能力检查，不隐式上传合成音频或请求整理服务。缺少必要凭据仍会阻止完成配置。服务探测由用户明确点击 Probe / 测试按钮发起；单次探测不证明真实识别质量或端到端交付。

自定义 OpenAI-compatible 服务可为转写和 AI 整理共用一个 endpoint 与 API Key，并分别配置模型。只有用户明确选择对应阶段后才会探测或发送请求；阶段测试使用草稿 endpoint、模型和输入的 key，不保存 key 或切换正在使用的路线。「保存并使用」才会应用草稿。ASR base URL 不接受含用户名或密码的 userinfo；endpoint origin（协议、主机或有效端口）改变后不会把原 Custom API Key 发送到新 origin；同一 origin 下的路径变化不解除绑定。远程服务需要新填的服务商或 Router key，本机免 key 只允许 loopback 地址。AI 整理高级参数是默认空对象的有界顶层 JSON，只用于 Custom cleanup，并随日常短 / 长录音、History 重新整理 / 重试、写作预览和 cleanup 阶段测试发送至所选自定义 endpoint。空对象保持原请求字段。JSON 中禁止覆盖认证、请求协议、模型、消息、工具和输出形状；参数有大小、深度和字段数上限，已知字段另有类型与范围校验。`repetition_penalty` 的范围为 0–2；`reasoning_effort` 最多 16 个 Unicode scalar，单个 `stop` 字符串最多 256 个 Unicode scalar。未知的有界 provider 扩展字段会原样发送，因此不要在 JSON 字段名或值中放入 API Key、凭据或其他秘密。诊断可保留字段名、数量及有限的已知数值 / 布尔控制值；字符串和嵌套扩展值会遮蔽。自定义参数只在选中该自定义服务的整理请求中发送。

如果 Groq 密钥因 macOS Keychain 授权暂时不可读，用户可在前台 Settings 的 Groq 行点击「从钥匙串重新读取」。该操作只查询当前应用固定的 Groq Keychain 项；不写入、替换或迁移凭据，不连接 provider，也不把密钥交给前端。成功后密钥只在当前进程的内存设置中可用；重启后仍可能需要再次授权。取消、缺少项目、权限不可用、设置变化或 Settings 页面关闭时，现有设置保持不变。普通启动和后台读取仍禁用 Keychain 用户交互；该入口不证明或修复持久 ACL / 签名访问问题。

### DashScope Qwen Audio 3.1 Message

可选 provider `dashscope` 只接入精确模型 `qwen-audio-3.1-asr-flash-message`，用于保留独立原始 ASR 的 Message WebSocket 路径。设置中的 Beijing / Singapore 选择保存为 HTTPS origin `https://dashscope.aliyuncs.com` 或 `https://dashscope-intl.aliyuncs.com`；请求解析为相应官方 WSS host 的 `/api-ws/v1/inference`，使用 `Authorization: Bearer`。VoiceFlow 不使用 Workspace ID。连接先发送带 UUID 的 `run-task` 与 duplex mode，等待 `task-started` 后上传完整音频，再发送 `finish-task` 并等待明确的 `task-finished`。

该接线发送 `disfluency_removal_enabled:false`、关闭 interim results，只将最终句子作为原始 ASR；原生润色没有接入，后续 cleanup 仍由 VoiceFlow 单独执行。普通 HTTP `qwen-audio-3.1-asr-flash` 不是这条 Message 接线，VoiceFlow 不据此宣称它能关闭润色并取得原稿。句子或词的时间戳仅在服务实际返回时使用，单位为毫秒；`task-finished` 的累计 usage 只记录一次，不把逐条消息的累计值相加。模型文档给出的 7168 输入 / 1024 输出 token 限制使整段长音频有输出预算风险；VoiceFlow 以保守大小做有界重叠分段并完整覆盖音频，不截断尾部。服务账号、区域权限、识别质量和延迟均未在实现阶段验证。

HTTP ASR 上传 16 kHz、单声道、16-bit PCM WAV。应用单次直接 ASR 请求上限为 10 分钟；更长的录音会按完整覆盖分段处理，录音本身最多 15 分钟，不会截断尾部。用户可把分段阈值设在 5–3600 秒、目标段长设在 15–60 秒；长路径仍完整覆盖录音。SiliconFlow adapter 另执行 1 小时与 50 MB provider 文件限制，Mistral 文档限制为单次 3 小时；Fireworks 没有在此接线中声明 provider 时长或文件上限，10 分钟是 VoiceFlow 的请求限制，不是 Fireworks 服务声明。

SiliconFlow 的 SenseVoice 与 Qwen 请求只发送 multipart `file` 和 `model` 字段，语言行为为自动检测；此接线不发送 language、context/terms 或 `verbose_json` 等 metadata。Fireworks Whisper 同样以 multipart `file` 和 `model` 上传，使用自动检测，不请求术语提示、时间戳或置信度。Mistral 使用 multipart `file` 和 `model`：省略 language 时自动检测，也可指定单一固定语言；可发送最多 100 个词条的 `context_bias`，不会发送 Whisper `prompt`，也不使用置信度。Mistral 只在自动检测时请求片段时间戳，指定固定语言时不请求时间戳。除非用户另外配置了准确识别级联，ASR 只请求当前选定的 provider；该级联若触发，也只请求用户另行配置的 provider。失败不会静默切换到其他服务。ASR HTTP 请求不跟随重定向。

当用户选择 OpenAI `gpt-transcribe` 时，已晋升的专有名词会作为 `keywords` 发送，而不是整本词典。本机 Whisper 不会把 ggml 下载进 App，需要本机已有 whisper.cpp 或 speaches。启用 AI 文字整理时，转录文本会发送到用户配置的整理服务（默认为 Groq；也可改为 OpenAI、SiliconFlow、DeepSeek、Anthropic、Ollama、VoiceFlow MLX、VoiceFlow llama.cpp 或自定义端点）。转写和润色可以不是同一家。普通和长录音在发起整理请求前，会在本机执行语音标点、有限布局解析、已授权词典替换和同短语明确改口。整理请求以本地准备稿作为编辑目标。只有 Groq 执行隐式 Cleanup 且原始 ASR 与准备稿不同时，请求构造器才省略原始 ASR 参考，以准备稿作为唯一文本依据；原稿仍保留在本机 History 与来源记录。其他 provider 和明确选区 / 操作沿用原有来源参考行为。发送的文本只到用户选择的整理服务，不附带本机修订范围或 proof 元数据。

每个模型整理请求（普通 Cleanup、口述或 History 的 rewrite / shorten / formalize / casualize / translate 命令、History 重新整理与重试、写作预览和评测）都使用同一个共享 prompt：transcript、可能附带的原始来源、前一 chunk、获准的可见上下文、用户风格偏好、明确批准的风格样例和有界 `pairs_hint` 分别作为转义后的 JSON 字符串引用数据发送；这些数据中的指令文字不会成为 prompt 指令，也不会发送整本个人词典。已授权 Translate 请求会携带现有授权路径确定的目标：全局 Translation 模式使用设置中的目标语言，显式口述的 Translate intent 使用该操作解析出的目标。目标只授权翻译方向，正文不能选择或改写它。原始 AX role、窗口标题、URL、修订 proof 和权限不会作为独立请求元数据附加，但用户口述内容本身可包含 URL 等 literal。AssemblyAI 的 Code 模式使用 raw Sync，不使用 fused Dictation 改写；其它 Code 模式不请求共同 Cleanup。输出模式和有效整理强度只用于本机选择共享 system policy，不新增保存字段或 provider metadata。

若用户显式选择 Ollama 本机整理，VoiceFlow 使用本机 Ollama 上的 `qwen3.5:4b`，不会自动安装 Ollama 或拉取模型。设置里的状态检查由用户主动触发；它检查已保存的本机地址和模型状态，不会更改服务端配置。单个请求的消息内容最多 4096 UTF-8 字节（包含系统提示）；超限、输出预算耗尽、工具响应或不完整回复均失败关闭，并按本地规则处理完整准备稿，不把模型未完成的前缀作为成功候选。

LM Studio 本机整理路线已在设置 schema 27 退役：VoiceFlow 不再连接 LM Studio 服务或调用 `lms` CLI。旧设置中的 LM Studio 选择在加载时迁移为 VoiceFlow 管理的 `on_device_mlx`，它运行同一个 Qwen 3.8 27B MLX 6-bit 模型；旧的 LM Studio 模型 ID 改为 `qwen3_8_27b_mlx_6bit`。迁移前的设置以去除密钥的 `settings.json.pre-migration.bak` 保留一份。该模型尚未在 VoiceFlow 中下载或导入时，整理按本地规则回退，不转向云端。


用户主动启动选中文本操作后，VoiceFlow 通过辅助功能读取这次选区、受支持的可编辑字段全文或空回复框，并把捕获到的文本和语音指令发给用户配置的整理服务。来源超过 16 KiB 会在请求前被拒绝；无法取得精确选区或原字段版本时，来源只能生成预览，不能用于替换。VoiceFlow 不从现有剪贴板猜测来源。确认或复制前，结果和用户编辑只存在于这次内存预览；它们不会进入普通 History、HUD、日志、导出、个人词典或风格学习。确认前会复核目标和来源；在交付前发现变化或无法验证时复制预览结果，不修改目标。若已经尝试写入但系统不能确认交付状态，会安全报告未验证，不盲目重试。

起草回复是选中文本操作中的独立受限类型：目标必须是空回复框，并且当前 App 规则须分别允许读取辅助功能文字和将该文字发送给 provider。只有这时才会捕获有界的附近页面文字；这是一次明确操作，不代表全局或默认上下文许可。发送请求前（包括等待限额和重试）会再次核对权限、页面目标和来源版本；撤销许可或目标变化会丢弃这次请求，即使随后重新授权也不会恢复旧请求。目标标题、原始 URL、查询参数、片段和页面身份只用于本机路由与目标安全检查，不发送给整理模型。手动「看屏幕」热键仍是另一项独立操作：需配置视觉模型和屏幕录制权限，截取当前窗口一张内存 PNG，发给用户配置的 vision provider 并先弹出预览（替换 / 只复制 / 取消）。取消或关闭预览会丢掉图片；History 不保存截图。选中文本或看屏幕的语音指令也走现有录音 / ASR 流程；ASR 失败时完整录音按恢复策略保留在 History，长录音按完整覆盖分段重试。History 重试只复制，不恢复原操作目标；macOS 会在内存中捕获有界的本机剪贴板快照，沿用 pasteboard owner 的完整 item/type/data 复核和临时 marker/text 所有权证明。快照不持久化或发送给 provider；起始读取失败或内容已变化时不写入剪贴板，识别结果保存到 History 供用户显式复制。其他平台没有相同 native item-level 准入能力时也只保存 History。AppKit 没有原子 compare-and-write，最终复核和写入声明之间仍有窄竞态。成功操作的选区、指令与预览仍不进入普通 History。会议录音、Spark 和生图仍不提供。

自动上下文的文字和图像权限单独逐 App 管理。`context_enabled` 是总开关；每条现有 AppMapping 的 `source_permissions` 分别控制 AX 文字、本机 OCR、云端视觉和将已识别的上下文文字发给配置的 ASR / cleanup provider。四项新增权限缺省均为关闭；旧的总上下文开关、App mapping 或 `window_ocr_enabled` 不会授予 AX 文字、provider 文字或云端视觉。升级前若用户已显式打开全局窗口 OCR，则仅为迁移时已有的规则保留 `local_ocr=true`，仍由全局 `window_ocr_enabled` 总开关控制。本机 OCR 描述的是识别位置，不代表其派生文字永远留在本机：只有另外打开 `context_text_to_providers` 后，受允许的 AX / OCR / 云端视觉识别文字才会进入用户配置的 ASR / cleanup 请求。屏幕提取的术语也只有在该 provider 文字许可有效时才可用于全局词典学习；仅允许读取 AX、OCR 或视觉文字不会把屏幕词条写入词典。

设置预览和空闲场景预览只在用户完成引导、打开 `context_enabled` 且没有录音或其他操作时刷新。总开关关闭或尚未完成引导时，后台不轮询前台应用，也不读取焦点字段、窗口标题或浏览器状态；设置改变后，缓存预览只在本机按 General 策略和当前手动覆盖重新整理，浏览器状态标为关闭。跳过的后台预览不会增加检测代次或改写录音会话已冻结的目标。用户主动开始听写、选中文本或看屏幕后，操作仍会按原有目标安全流程重新读取所需焦点信息；即使自动上下文关闭或引导未完成的「试用」仍会保留这次手势授权的新输入类型分类。

规则可要求 App bundle、可执行文件、host、页面路径前缀、焦点字段的任意组合；所有已填写的条件必须同时匹配。host 和路径仅在本机用于路由；raw URL（含凭据、查询、片段）、窗口标题、PID 和目标 identity 不会进入 provider payload、普通 History 或导出。具体网站 / 路径 / 字段规则按确定的特异性顺序胜过通用浏览器规则；缺失信号不满足已填写的条件。场景会使用正向字段证据细化：IDE 的通用编辑字段不会自动当作 chat prompt；GitHub 的 issue / pull request 标题、正文或评论只在对应页面和可识别字段标签同时匹配时区分；Slack / WeChat 的搜索字段按 Search 处理。原始辅助功能字段标签只用于本机短暂分类，不保存在上下文或发给 provider。

自动内容提取只读取匹配规则明确许可的有界 AX 字段；云端视觉只允许绑定到具体 App / 可执行文件规则。若授权的 AX 证据已足够，不截屏；若仍不足且 `local_ocr` 与全局 OCR 开关都开启，则检查屏幕录制权限后至多截取当前窗口一张内存图用于本机 OCR。若结果仍不足，且同时有具体 App 的 `cloud_vision`、`context_text_to_providers`、已配置的 vision provider / model 和屏幕录制权限，则把同一张图作为自动云端视觉回退。AX 与 OCR 内容足够时跳过云端请求。不会捕获整屏、不会静默更换 provider / model；权限被撤销、会话取消或目标 / 页面变化后会丢弃待用证据和结果，保留原始录音用于正常安全回退。图像只在内存中短暂存在，不进 History / 导出 / 日志。

mapping 保留的风格样例另有 `style_examples_approved` 明确许可，与一般文字 provider 许可互相独立。旧记录中来源不明的样例会留在设置中，但缺少该字段时按未批准处理，不会进入 prompt，直到用户复核批准。自动观察到的短风格改写先进入待确认草稿；用户明确确认某条草稿后，只批准该条样例，其他未审核样例不会随之获准。密码字段、银行 / HR / SSO / 密码管理器和关闭学习的预设仍受保护。手动选中文本快捷键只授权本次选区，不自动附带无关的邻近 AX 文字；手动看屏幕权限不会授予自动上下文截图。

场景和目标检测在本机完成。浏览器 host / path 匹配只有在用户开启浏览器访问后才会执行；macOS 可能为此请求 Apple Events 自动化权限，用于读取浏览器页面身份。该权限不授予 AX、OCR、截图或 provider 访问。当前页面身份（包括查询 / 片段变化）只在本机用不可逆 fingerprint 绑定请求结果与交付目标；原始 URL、凭据、查询、片段不序列化。

HTTP batch provider 可以在录音期间批量预取已完成分块；这些预取文字不显示在 HUD，也不会写入目标 App、剪贴板或 History。Soniox 使用独立的真流式路径，不启动相同音频的 batch 预取；录音中的 provisional token 不进入 cleanup 或持久化数据。停止录音后，准确识别级联可能仍产生主识别 partial 事件，但当前生产 HUD 不展示这份草稿；这些事件只更新窗口内的非最终 HUD 状态，不会直接写入最终稿或持久记录。若主识别结果随后被现有级联选为最终稿，仍由该正式结果路径处理。X2 的 HUD 草稿展示尚未实现。

粘贴后只有在已有 App mapping 明确允许辅助功能文字，或用户在词典设置中单独打开「本机观察插入后的改动」时，才会尝试同字段观察。独立开关默认关闭。学习事实只由原 paste owner 在预期 UTF-16 splice 与实际 AXValue 完全一致、焦点仍是同一目标且 `PasteVerificationFact::Verified` 时创建；`VerifiedFullRange` 不授权学习。事实绑定粘贴前长度、替换范围、插入后范围和原焦点字段 anchor，观察复用该 anchor 与有界 UTF-16 读回，不再以唯一子串搜索重建插入位置。只观察由确认范围及未变前后锚点定位的片段；锚点变化、目标变化或范围无法对应时不学习。观察最多持有 12 秒绝对 read lease；owner 在每次同步 AX 调用前后复核 observation epoch、取消和 deadline，失效后不再发起下一项 AX 读取。已开始的同步 AX 调用不能被抢占；所有在途 learning AX 调用真实返回且 read lease 关闭后，研究学习任务才报告本地闭合。观察与学习都在本机进行，不会立即调用 provider，也不会上传整个 field 或周边文字；只有之后用户主动发起听写 / 整理时，当前 route 支持才会携带 bounded、scope 匹配的已晋升词对提示。本机 ASR 当前没有词表 / decoder 控制；此开关也不启用其他屏幕文字、OCR 或屏幕词条收集。关闭独立开关撤销该项授权；已有的单独 AX 文字许可仍按原设置生效。密码框 / Secure Input、焦点或字段身份未知、目标或字段改变、该 App mapping 关闭学习、或 1Password / HR / SSO 等预设关学习的目标不观察。

AX 观察的 B1b 文本路径最多从一次有界编辑中提取 1–3 个互不重叠的局部词语纠正；它先逐个检查所有 hunk，再去重。对自动学习和 SQL 持久化而言，任一 hunk 不满足既定自动词汇资格时，整次编辑都不自动持久化，不会只持久化旁边看似安全的词对；现有规则对已覆盖的日期、金额、数字和否定反例会拒绝自动学习，这不代表具备通用的对象语义识别。结构建议仍可能列出待确认词对，例如 `Plane` → `Place`；结构建议与自动资格是分开的判断。`Reakt` → `React` 目前没有自动学习依据。风格记录仅接受明确的整次变换，内容变化不会回退为 style；现有晋升与强度门槛未变。此文本与隔离研究切片不证明真实 AppState 的多词对粘贴观察、同一 Host 的纠正后读回、IME 行为或学习收益。History 与 local-only 路径仍使用保守的单词对 gate。

用户在 History 明确编辑并保存时，VoiceFlow 会将新版本和同一 SQLite 事务中读取的既有采用文本、App mapping 与 scene 一起比较。该路径只接受现有词典分类器认可的单词拼写纠正；追加 / 删除、数字、否定变化和多词或一般改写不会晋升，自动晋升也保守拒绝跨文字系统替换。连续中文长串里的同音人名若没有明确分隔边界，会跳过候选，不把相邻语境片段当作纠正词；完整有界的 2–3 字姓名仍按现有同音规则和 2 次人名门槛处理。它不要求 AX 字段读取许可、不分析原始 ASR 来归因、不生成风格样例，也不把词条追加到全局个人词典；晋升后的自动 scene pair 在同一已验证 scene 内具备本地替换和整理提示资格，目标词仍只属于该 scene。scope 匹配仍不足以解除既有目标 / 任务保护：普通 Code、Secure、Terminal、Form、Search 等不会仅因 scene pair 命中而自动替换或生成整理提示。只有有效且明确的 `PromptOrCode` 声明可将 Code 的整理输入按 `CodingPrompt` 处理后，再依现有规则使用；本机观察许可不会改变这些限制。候选仍走同一场景范围、3 次术语 / 2 次人名晋升、忽略与 tombstone 保护。相同 History 行的相同纠正只计一次，不同 History 行可作为独立编辑计数；若具有同一 dictation origin，则跨渠道按该交易去重。

## 本机麦克风自检与词典反馈

用户主动点击麦克风自检后，应用最多打开输入流 30 秒，只在内存测量音量、峰值、收到帧 / 信号状态和保存的输入增益。自检不会创建录音文件、恢复 spool、History 或 transcript，不调用 ASR / 整理 / 视觉服务。需要已获麦克风权限；未获准时提示前往权限页，不在自检中自动申请。停止、离开页面、窗口隐藏或失去焦点、音频设置变化或正式听写开始时结束。用户在开发构建中已明确开启常开麦克风时，自检结束后仍恢复该空闲流，其样本继续丢弃；发行构建忽略已保存的开启值，并拒绝该设置字段更新。

首次引导的本机路线明确关闭 AI 整理，只做本机转写；用户可之后另行选择整理服务。选择 On Device 不等于启用严格离线，模型下载仍是用户主动发起的网络操作。

个人词典反馈保存在 history SQLite 的 `learned_term_usage`（schema v13），仅包含实际本机词典替换的目标词、按处理次数和最近替换时间；不新增整段转录、音频或目标 App 数据。History 当前 schema 为 v19。`learn_observations` 保存纠正来源类型、适用时的 History 行 / revision ID、配对规则 key、dictation transaction origin、channel 和 proof eligibility；key 由小写 before / after 词面组成，origin 是本机 transaction ID。这些是词对与来源元数据，不是整段转录或完整输入框文字。只有被接受且 origin 可验证的纠正 proof 才参与自动门槛，同一词对的同一 transaction 只计一次；旧 opaque receipts 的来源保持 unknown，既有 hits 保留为历史值但不并入新的自动门槛。已关联 History 行的 receipts 会随 History 删除或保留期清理而级联删除；没有 History 行引用的 paste receipts 不受 `keep_history_days` 保留期清理，只受 4096 条上限约束，超出时淘汰旧条目；清空全部数据会删除它们。`Settings.dictionary` 的来源所有权区分 `manual`、learning rule、screen 与 `legacy_unknown` 等来源；旧设置中无法证明来源的词会标为 `legacy_unknown`，不推断为手动添加。`Clear All Data` 会删除 History 数据库中的学习记录与词对，但 `Settings.dictionary` 及其词条来源所有权会随其他设置保留。History 的新记录还可保留 `cleanup_attempt_kind`、`cleanup_failure_reason`、`cleanup_final_guard_reason` 与 `cleanup_transformations`：分别表示有界整理请求类别、首次整理失败原因、独立最终输出保真检查原因和实际接受回复中的响应调整代码（`restore_spoken_layout`、`restore_prepared_preamble`；较早记录还可能含已停用的 `strip_internal_cleanup_metadata`）；这些字段不保存服务商原始错误文本或额外的已接受候选正文。旧记录缺少这些字段时保持未知，不推断为「未调用」或空调整列表。旧 History schema 升级会保留原记录，并在应用新 schema 前生成私有备份；不支持的新 schema 会拒绝打开，不做降级写入。

`learn_pairs.auto_scoped`（schema v16）只标记由新的 History / 本机局部观察路径晋升的自动 scene pair；它不替代当前 family、mapping、browser host、bundle 的逐项匹配，也不解除普通 Code、Secure、Terminal、Form、Search 等目标的既有应用限制。内置 Codex (`code.codex` + `com.openai.codex`) 有窄例外：观察仍为 Code 时，只有完整 ASR 转录明确表达自然语言请求且未呈现代码、命令或结构化数据，当前整理事务才按 `CodingPrompt` 路由；它不改写观察分类、不扩展到其它 App / mapping，也不启用自动词典学习。其它 Code 输入仍需有效且明确的 `PromptOrCode` 声明才按 `CodingPrompt` 处理；该标记不会把目标词加进全局词典。每段处理按词条去重，包括用户主动进行的 History 重新整理；从功能启用后记录，不推测旧收益。记录在本机准备阶段生成，可能发生于后来取消、回退或未确认交付的处理，因此不用于声称准确率或成功插入。词条没有生效规则后不再展示对应收益；「清空全部数据」会删除 History SQLite 中的学习记录，但 Settings 中的全局词条及其来源所有权会保留。上述记录不会自动上传。

用户也可在词典设置中主动建立一条 before → after 手动纠正规则，并从当前运行的原生 App 列表选择其 bundle 范围。规则文字与 bundle 保存在本机 history SQLite 的 `learn_pairs`，只在该 App 身份已知且匹配时生效；此操作不会写入全局个人词典或改动既有 History。点击「忘记」会用现有 tombstone 撤销规则。当前入口不接受浏览器 scope；无法读取或确认 App 时拒绝保存，不把未知范围当作全局。

## 本地数据

以下数据保存在 Tauri app_data_dir：

- History SQLite 与其本地 `history-pending/` journal：provider 原始 ASR 文字（`asr_text`）、ASR 响应明确返回时才保存的独立融合候选（`provider_cleaned_candidate`）、语义保真检查拒绝的完整 cleanup 文本（`cleanup_rejected_candidate`）及非敏感的阶段 / 原因码（`cleanup_guard_reason`）、本地处理后的识别草稿（`raw_text`）、通过最终保护检查的听写结果（`final_text`）、实际产出识别草稿的 ASR provider/model（`engine`）、状态、delivery/fallback 信息和经过过滤的 context policy。普通成功听写不会持久化被接受的 cleanup 结果；语气试跑只在内存响应中分别返回共享 adapter 接受后的 `model_candidate` 与最终 `text`，并在适用时返回 typed rejection stage/reason。该候选不是未经处理的原始模型 wire response。AX/OCR/视觉原文、图片、raw URL、窗口标题、PID、目标 identity 和风格样例文字不序列化；风格样例的当前批准状态只从设置重新读取。候选列允许为空，旧记录迁移后 `asr_text`、`provider_cleaned_candidate`、`cleanup_rejected_candidate` 和 `cleanup_guard_reason` 均为空；不会猜测补写缺失的候选或 provider provenance。合法完整的 cleanup 文本若被语义保真检查拒绝，会与可能来自 ASR 的候选分开保留在本机 History；它受现有 History 删除、清空和 JSON 导出行为管理，不进入普通日志 / 诊断，也不会作为后续 provider 输入。History schema v19 包含这些 nullable 字段、粘贴交付的稳定错误码 / 安全用户提示列、带有词对 / origin / channel / proof eligibility 的学习 receipts、learn pair 的待同步字典 action/version，以及默认为 false 的自动 scene pair 标记；旧的 opaque learning receipt 保持 unknown，旧 learn pair 不会被批量升级为自动 scene pair；历史 JSON 导出包含这些 nullable 字段。普通粘贴前会在本机以稳定 transaction ID 写入有界 pending intent，状态为 `delivery_pending`，不预先声称已插入或已保存；只有交付 owner 返回结果后才更新同一 intent 并尝试提交 SQLite History。若进程在交付后、History 确认前退出，启动恢复将 pending 记录标为交付未确认并保存精确文字，不会自动重新 ASR、整理、粘贴或重试。History-only 等模式没有外部插入副作用；写入失败仍显示保存失败。普通听写的 guarded 键盘快捷键一旦可能已发出，主 HUD 立即收起；AX 读回与剪贴板 ownership 结算继续在后台完成，Processing phase 和 live operation lease 在此期间保持占用。读回确认粘贴后，live operation 结束时不等待可选 History 或 gold-audio I/O；其有界 retained job 继续持有清空 fence 与 payload 直到 I/O 完成，之后才报告 History ACK。History 写入只保存在本机；用户可设置 History 保留期限，选「永久保留」时不自动清除实时 History；但 schema 迁移备份最多保留 7 天。History 删除与「清空全部数据」会按上文的关系清理其关联学习记录，学习数据库数据不会自动上传。
- recovery spool：失败或中断录音的 WAV/F32 分块。成功编码后，捕获 spool 的关闭 ownership 转交给同一 History handoff；交付前 journal 会在音频保留允许时引用该 session 的预期 recovery WAV。History 确认前保留源 spool；交付未确认、失败或降级需要恢复音频且 `keep_audio_days` 允许保留时，以现有 manifest 建立可重试音频，其他成功 History ACK 后移除临时 spool。History ACK 失败时，源分块留给下次启动恢复。短录音和长录音共用这一 transaction；长录音的 chunk spool 只在未由 capture spool 覆盖的恢复路径保留。若本次 History 保存失败，HUD 会提供该 session 的显式 History 保存重试；重试只读取或重建其本地 spool 并写入 History，不启动 ASR、cleanup 或粘贴，失败会保留 spool 和重试入口。若 spool 已过保留期限、被清除或无法恢复，HUD 只提供检查 History，并将结果标为未确认，不声称音频仍在或已经保存。保留期限遵循 `keep_audio_days`；
- 录音捕获的 PCM 另有最多 15 分钟的本机内存上限。录音开始只在内存中预留 spool session 路径；独立有界 worker 在后台独占创建目录、manifest 并写入 F32 recovery chunks，失败时不会覆盖已有恢复目录。stop 返回已编码音频与捕获 spool lease，不等待阻塞的 spool 文件操作；常规捕获和 spool worker 有界且互相隔离，已完成但待 History ACK 的 spool 不占用 retained History job 的队列。若初始化或写入 owner 尚未退出，恢复读取会返回 busy，删除会留给 owner 清理其创建的目录，清空数据会报告 spool 清理待完成。若 session ID 碰到已有 recovery 目录，初始化会失败并保留其内容；owner 关闭后可再次执行清空。转交后的 lease 只由 retained History owner 依真实 outcome 请求 Completed 或 Recoverable；调用方超时不会取消实际文件 I/O。此期间本次内存音频可以继续处理，但不把 spool 报告为完整或可恢复，也不会复用该会话目录启动下一次录音。实时写入 scope 由注册的 session lease 推导，并只覆盖该 session；旧式平面恢复 WAV 使用其确切文件 scope。删除 lease 在 session 停止写入后只允许清理，不会恢复写权限。清空、保留期清理和未绑定 session owner 的旧式恢复写入仍使用 RecoverySpool 根 scope。恢复 spool quota walk 会枚举整个 spool 树，但执行时持有的是当前 session 的派生 permit 与 per-root scan marker；同根新的 quota reservation 等待到扫描结束，入账采用扫描开始和准入时较大的 in-flight 总量，不同根可以独立进展。gold quota 单独使用 GoldAudio 根 scope 统计 gold 树。根维护竞争由有界 spool worker 保留并重试已接受的 PCM，不在音频 callback 上等待；超额或无法保留时不会把尚未确认的音频报告为持久化；
- History 导出文件使用原子写入并设为 Unix `0600`；已存在的用户选择导出目录权限保持不变。设置文件若在保存前发现格式损坏，会先将原始字节备份到 `settings.json.malformed.bak`（Unix `0600`）；该备份可能包含旧设置中的敏感字段并保留到用户自行处理。provider 整理失败日志只记录固定失败类别，不记录原始服务商错误详情；面向用户的错误详情行为不变。
- gold wav：仅在设置中主动打开「成功听写也保留音频」后，成功听写才会写入本机 `gold/`（默认关；配额 4 GB；满则停止新写，不挡听写）；
- usage：按天保存 ASR / LLM 请求数和录音时长，与 History 使用相同的 `keep_history_days` 自动保留期；永久保留 History 时 usage 也不会按期清理；
- `diagnostics/paste-delivery.jsonl`：仅记录粘贴失败、读回未确认或临时剪贴板写入后的取消诊断。字段包括阶段、目标 App bundle ID、Accessibility / 焦点验证、剪贴板 snapshot 与 ownership、键盘粘贴是否尝试 / 可能发送、typed paste verification fact 和旧剪贴板恢复结果。验证 fact 区分快捷键结果未知、预期插入无法构造、目标 / 焦点未确认、读回不可用、读回不符、AXValue 精确确认与完整范围确认；`paste_verification_delay_ms` 只表示读回前固定等待的 250 ms，不是实际读回耗时。之后在同一保留 AX field anchor 上按固定间隔观察（已知预期 splice 时最多 10 次轮询、排程等待合计 1.8 秒，否则仅 5 次、300 ms；不含最初 250 ms 等待或原生 AX 调用耗时，不承诺墙钟时限）；首次出现具体 AXValue 不符时至多尝试一次受限完整范围读取（折叠光标或空字段也适用；替换文字与原选区相同时 AXValue 相等不算确认，改为在轮询的第 1 次、第 5 次和最后一次最多各尝试一次完整范围读取，不可用时停止轮询；无此证明则记为读回不可用的未确认结果，不算成功），只有完整文本、UTF-16 长度、原选区对应的插入后光标位置及前后目标 / 焦点身份均吻合才可确认。该路径不剥离换行或归一化正文；没有粘贴前完整 AXValue 时不升级为完整范围成功，也不会发送第二次快捷键。日志不含输入框值、剪贴板正文、预期或实际插入文字、transcript、窗口标题、URL、PID、密钥或原始系统错误。临时剪贴板使用 plain-text、唯一 owner marker，以及 `org.nspasteboard.TransientType` 和 `org.nspasteboard.AutoGeneratedType` 两种临时内容提示；这些提示供兼容的剪贴板管理器参考，不保证它们都会忽略该内容。发送快捷键前取消时，只有快捷键确定未发出且本次 marker 仍通过最终所有权复核，才通过既有恢复 owner 恢复原剪贴板；恢复结果按实际提交记录。快捷键可能已经发出时绝不因取消恢复；marker 已变化或所有权未知时保留当前内容，并由 History 提供恢复路径。取消前尚未写临时剪贴板不会产生此类记录。新记录写入时删除超过 30 天的行，并从最旧记录开始裁剪，使文件不超过 10 MiB；启动时也会执行保留期清理。文件夹 / 文件在 Unix 上限制为 `0700` / `0600`；
- settings：新建或替换的 API Key 只写入 macOS Keychain，并在读回验证成功后才清除旧来源；安全存储失败会报 `credential_storage` 错误，不会新建或覆盖明文 sidecar。升级留下的 `settings.json` / `secrets/` 明文密钥会在 Keychain 写入并验证成功前保留；读取失败不会当作密钥不存在，也不会用旧 sidecar 覆盖现有安全凭据。非服务偏好（例如输入设备、主题或快捷键）使用结构验证保存，不检查服务就绪，也不读取、写入或删除现有 Keychain 凭据；未验证的 `settings.json` 密钥原样保留，`secrets/` sidecar 保持不变。服务路由、密钥和首次设置完成仍执行原有就绪与安全存储验证。安装版 Test 应用按其 Tauri bundle identity 使用独立的 Keychain service 名称，不读取或导入普通 VoiceFlow 的凭据，也不迁移普通应用的 History 加密密钥；两个 bundle 的正常存储相互隔离；
- `style_drafts`：History SQLite 中尚未批准的写作风格草稿，含 mapping ID、style key、excerpt、修改前后片段及最近一次 upsert 时间；它们可由 DictionarySettings 查看、确认或忽略，确认后进入现有用户设置并删除草稿。草稿与 History 使用相同 `keep_history_days` 自动保留期，设为 0 时永久保留，清空全部数据会一并删除；
- `models/`：用户主动下载的 On Device ASR 权重与 VoiceFlow 管理的 MLX / GGUF cleanup 模型目录按固定清单校验；新 cleanup 下载仅开放固定的五款 MLX 模型。已安装的其他 MLX / GGUF 文件仍可管理，当前保存的旧路由保留。GGUF 权重按固定 Hugging Face revision、字节数和 SHA-256 核验；导入 MLX cleanup 模型用 APFS clone 保留来源目录，删除只针对管理副本。已保存的 GGUF 路线由随包 llama.cpp 通过私有 Unix socket 在本机运行，并以 `--offline` 禁止 helper 访问网络；不再提供新 GGUF 下载或选择。下载需要用户主动操作和网络连接，运行时不会上传模型或整理文本，也不需要安装 Ollama。模型文件状态、首次加载和驻留状态不证明实际识别或整理质量。VoiceFlow 不在启动时下载模型，也不会自动安装 Ollama。清空全部 history / spool / gold **不会**删除模型。
- `models/audio-tmp/`：仅供本机 sidecar 使用的私有临时音频目录，与可恢复的 History / recovery spool 分开。每次音频处理结束、失败或取消后按持有的文件身份尝试清理对应临时文件；失败保留 owner，正常退出也会进入有界的 sidecar 终止和已知临时音频清理流程。无身份依据的历史崩溃残余不自动删除。

History 恢复 HUD 的文字复制只在用户点击时发生。Tauri 事件与 action 参数携带 opaque delivery transaction、session generation 和 History transaction 身份，不携带 transcript；后端只读取匹配的、有界 pending intent 或完全相同 transaction ID 的本机 History 行。intent 使用现有 History 字段与 context policy 过滤，不新增脱离 History 设置的文字日志。复制只写剪贴板，不会重新转写、整理、粘贴或自动重试。确认读取失败时可由用户再次点击；剪贴板写入已尝试但结果未知时将明确显示 unknown 并禁止重复写入。关闭恢复面板不会删除 journal；新录音和清空数据会按相同代次 / root lease 规则撤销旧 ticket，迟到状态不能恢复隐藏 HUD。

Test Groq 凭据导入 / 状态 CLI 仅编译在显式启用 `research-harness` feature 的构建中。默认生产构建会在 Tauri 启动和单实例转发前拒绝这些保留参数；单实例 callback 也会在解析普通动作、WAV 重放或聚焦窗口前拒绝已转发的保留参数。默认构建不含导入 / 状态处理或 Keychain 诊断 helpers；Installable Test 的正常 Keychain namespace routing 仍保持独立。一次性 Test Groq 凭据导入只接受最终签名的 Installable Test bundle 的固定 `--import-test-groq-key-stdin-v2` 参数；密钥通过有界、限时的单行 stdin 传入，写入新建的 Test Groq Keychain v7 主 / 回退项并读回核验。旧 Test Groq v1 / v2 / v3 / v4 / v5 / v6 项保留且不会被读取、删除或修改；普通 VoiceFlow、其他 Test provider 和 History 凭据不变。自签名 Test build 的 Keychain partition 可能绑定可执行文件的 CDHash，因此不同 build 不保证能读取前一 build 写入的凭据，测试流程可能需要由该 build 的最终 App 重新配置。该路径不会使用 argv、环境变量、明文文件、剪贴板或日志传递密钥，也不会发起网络探测。重复相同值可返回已配置；已有不同值、Keychain 不可用或核验状态未知时失败关闭，不覆盖现有项。固定只读命令 `--test-groq-key-status-v1` 可由最终 Test App 查询这两个现存槽位；它只报告固定状态、阶段、等待结果、耗时和可用的数字 OSStatus，不输出凭据、长度、提示、服务名或账户名，也不会写入或改变 Keychain。此前导入结果若为 unknown，该查询不会推断它是否成功。

macOS `research-harness` build 的 Installable Test bundle 另有固定 `--research-owned-wav <absolute-path> --target-nonce <uuid>` 入口，只接受内容 SHA-256 在代码 allowlist 中、且格式为 16 kHz 单声道 PCM16 的有界 WAV。它把同一份已校验字节定速送入正常 capture worker，再走正常 Stop、ASR、cleanup 与 paste 路径。默认 `native-native`；显式 route 还可选择 `native-groq`、`groq-native` 或 `groq-groq`。只接受固定的本机模型，或 Groq `whisper-large-v3-turbo` ASR 与 `openai/gpt-oss-20b` cleanup；云端路线要求对应 provider 凭据和非严格离线配置。开始及 claim 时均核对当前已保存设置；配置不匹配时拒绝，也不会为测试修改设置。后续请求沿用生产 provider 的重试、cascade 与保护策略，实际采用的路线以记录的 provider 结果为准。当前焦点还必须是 Chrome 的固定测试字段，或私有 nonce 绑定 TextEdit `.txt` fixture 中完整匹配该 nonce 的字段与 UTF-16 选区，否则失败关闭。TextEdit 另需固定私有目录下的规范文件 URL、UUID 文件名和初始窗口标题；两个目标都绑定当前 PID、窗口、输入字段、完整字段内容与选区并在插入前复核。该入口不恢复焦点、不改投其他字段，插入未验证时不回退到剪贴板。测试源不打开麦克风，也不会打开热麦克风、申请麦克风权限、改默认输入设备或读取其他进程音频。成功的测试记录只含固定源 hash、generation、采样 / 帧计数和阶段；目标准入失败的 stderr 诊断只含静态 admission / focus 阶段与原因码、稳定前台身份布尔值及有界 paste 错误码，不含路径、nonce、PID、窗口、字段内容、音频、识别文字或密钥；该专用 session 不写入学习观察数据。它验证软件回放接线，不代表物理麦克风链路已验证。

feature-gated `voiceflow-learning-harness` 还有一个 target-only V3 `ObserveTarget` 研究入口。它只接受生成的 `prepared.json` 中固定 source manifest、Recipe、Info.plist、helper / Host hash 和一个注册 FixtureHost bundle/control；操作会启动新的私有 FixtureHost session，通过 owned helper 读取同一注册 target control，再按 SHA-256 与 UTF-8 长度对照预声明值。当前 fixture 的实际值为固定 29-byte synthetic 文本；原始 sample 只留在权限为 `0700` 的 task-owned session helper receipt，stdio operation receipt 只输出 hash、长度和 AX/process metadata。此路径不初始化普通 Tauri app、普通 app data、Settings、Keychain，不写学习 arm SQL，不读取或修改其他 App 的字段，也不访问 clipboard、provider 或 product paste；为显示 owned FixtureHost，运行时会将该受控窗口置于前台。Helper 会在操作结束后等待 owned Host 退出；phase deadline 会取消并等待实际清理，若 CLI 正在同步处理该请求则没有独立的 in-flight cancel 命令。该样本只证明注册 FixtureHost 的单次独立 AX 组件读取，不证明 VoiceFlow 产品字段、真实粘贴、学习、最终稿或纠错链。

同一 feature-gated harness 有 named-only `--clipboard-guard-component`：它只在唯一命名的 NSPasteboard 上使用固定 synthetic seed，parent 在内存中持有该测试板的 snapshot / ownership proof，child 只通过固定状态码和 opaque lease 交互，不输出正文、旧数据或 hash。`--mainqueue-probe` 也通过 OS main-thread callback 与 owner join 检查；它不访问 AX、clipboard、Host 或 input source。另有 research-only `--clipboard-guard-general-component` 与 General clipboard owner 的私有实现；4 个错误参数组合在 clipboard capture 前拒绝。随后一次独立 `normal_restore` preflight 已通过：parent 与 child 均确认 exit 0，回执记录 `owner_retained=false`、`controls_sent=0` 和 parent restore commit。General 原 Snapshot、ownership proof 和 token 仅由 parent 保存在内存中，不经 child IPC，也不写入磁盘或日志。原始 flavor / bytes readback 未探测，driver 未读取或导出 General clipboard 正文或 hash，因此这不是原内容逐字节回读验证。该 preflight 未运行 Host、AX、TIS、`Cmd+V`、WAV 或模型；它不开放产品路径：`general_guard_active_for` 仍为 false，`RunOwnedPasteSession` 仍在 target 或 clipboard 副作用前拒绝。较早一次真实 General clipboard 尝试仍保留为 failed，未获正常 owner-close / restore 回执，原剪贴板恢复结果仍为 unknown；新的独立 preflight 不改变旧结果。named component、General preflight 和 mainqueue probe 均不能作为产品 `Cmd+V`、native delivery 或学习链已通过的证据。另一次独立 RemoteNamed recorder CLI probe 的 9 个 case 全部 accepted，parent / child 实际 wait 均 exit 0，owner 已结算；`controls_sent=0`、target dispatch=0、`shortcut_sent=false`。它只在唯一 named pasteboard 的 synthetic fixture 上使用 recorder/fake callback，不读取或导出个人剪贴板内容，不发送快捷键，不创建 `ConfirmedInsertion`，也不证明生产 paste、学习或真人编辑。

`get_latency_metrics` 本身只保存在当前进程的内存中，不写入上述粘贴交付文件。它返回有界的阶段延迟摘要、分组交付计数和固定错误 / 回退原因；最多保留 32 个 provider/model/path 分组，每阶段最多 128 个延迟样本。ASR 用量还记录实际 HTTP 请求数（包括队列重试）、失败请求数、可解码 WAV 的提交时长与对应请求数；Soniox 另记录流式尝试 / 失败数、session 墙钟时长、发送音频秒数和重放音频秒数。这些流式时长是诊断值，不等同于账单用量；provider 明确返回的最多 8 种固定用量单位和数量保持分开，不转换为费用。分组标签会过滤并截短。性能诊断不包含转录、音频、上下文、图片、目标 identity、URL、endpoint 或密钥。应用不会自动上传这些指标；只有用户主动选择“复制 JSON”时才会写入系统剪贴板，重启后样本清空。粘贴交付 JSONL 是独立的本机诊断记录，按上述 30 天 / 10 MiB 边界保留。本机 MLX 整理事件写入 `mlx-cleanup-performance.jsonl`，每个已完成请求记录模型准备和 cache plan 的有界毫秒值；常规 timing 事件还记录轻量 `cache_plan_timings`，不受 6 秒以上才记录 heavy phase snapshot 的门槛影响；旧 sidecar 未提供该字段或计时值校验失败时会省略。它按稳定用户前缀与仅系统输入分类，记录最多四次既有 `ModelContainer.prepare(input:)` 探测尝试及其墙钟时长，失败尝试也计数；另记录 `ModelContainer.perform` 调用至 closure 开始的墙钟时长（不是纯 actor 等待），以及既有 MLX `generate` 调用的墙钟区间，后者可能包括同步 suffix prefill/KV 工作。候选 prepare 总时长已汇总两类分类耗时，不要重复相加；这些细分计时均位于 cache plan 总区间内，也不能与其相加作为总耗时；它们只含有界次数与时间，不含整理文本、prompt、token IDs 或密钥。超过 6 秒时另含最多四个 sidecar phase snapshot，内容仅为有界运行时资源与时间数据，不包含整理文本、Prompt 或 token IDs，不能单独证明慢请求原因。同一文件也记录普通本机 MLX ASR 的 request ID、固定模型与 revision、transcribe/preload 操作、queue wait、模型完整性校验、sidecar session/handshake、实际 load/reuse、inference exchange 与 terminal 总耗时及 typed outcome；对有固定分类的推理失败，`inference_terminal` 事件还会附带有限的 `terminal_code` 枚举，未映射的情况省略该字段。它不包含转写文字、音频、prompt、token IDs、路径或原始错误文本；记录沿用 1 MiB 文件上限和 4 KiB 单事件上限，日志或诊断回调的故障不会改变识别结果；诊断发送器 panic 会在计时器内局部隔离，且不会重复发送。阶段耗时是嵌套的主机墙钟区间：sidecar session 包含 handshake，inference terminal 包含 exchange 和响应校验；各值不能相加作为无重叠总耗时。没有可靠来源的 child generation 不记录。

Stop-to-insert shared dictation trace uses the admitted stop timer's monotonic origin and keeps at most 256 coarse stage facts in process memory for that captured generation. Host intervals cover only observed ASR inference, request and MLX gate waits, prompt preparation, runtime startup, file validation, model load, final guard, paste submission, and target readback boundaries. Validated MLX prompt/generation durations and cache status are stored separately as typed child-reported facts; they have no host offsets and are never added to host elapsed time. Unknown prompt scope is represented as `unknown`; invalid optional timings are omitted. Sealing on delivery completion or timer drop closes open intervals and rejects late updates. Lines that older builds wrote with the retired `lm_studio_status_probe` stage no longer parse and are dropped the next time the file is rewritten. A content-free terminal summary is retained locally at `diagnostics/dictation-performance.jsonl` for 30 days, up to 10 MiB, and is removed by Clear All Data. Each line contains only a timestamp, captured session generation, fixed class/outcome/stage/scope/cache enums, and bounded durations. It contains no transcript, audio, prompt, provider/model/path label, endpoint, credential, error text, or window/device identity, and is not uploaded. Failed admission, a busy retained I/O owner, a write error, or a process exit before terminal persistence can leave a trace unrecorded. The offline evaluator reads only a file the caller explicitly selects; report generation does not scan the App data directory or upload its contents. Optional branch context is content-free metadata tied to that exact trace file hash and is reported with its supplied synthetic or captured-observed provenance.

成功听写的 gold 音频默认不保存。打开后仍跳过密码框 / Secure Input，以及 1Password、HR、SSO 等预设关学习的目标。音频只留在本机，不会上传，也不会写进普通 History JSON 导出。删除单条 History 或清空全部数据时，对应 gold wav 一并删除。导出训练音频时附带识别草稿，不使用 AI 整理后的 `final_text`，也不会自动写入词典学习。

当前默认保留策略：

- recovery audio：7 天；
- gold audio（仅 opt-in）：沿用同一保留天数；训练建议至少 90 天或 1 年；
- history text：365 天；
- usage：按天存储，与 History 文字使用同一保留天数；`keep_history_days` 为 0 时永久保留，清空全部数据会一并删除。
- 尚未批准的 `style_drafts`：保存 mapping / style、摘录及修改前后片段和最近更新时间；与 History 使用同一保留期，0 天时永久保留，清空全部数据会一并删除。

History 数据库升级会创建应用自己的 `history.sqlite.vN.bak` 回滚副本，可能包含升级前的转写。它最多保留 7 天；历史文字保留期更短时按更短期限清理，选择永久保留文字也不会永久保留回滚副本。只处理应用数据目录内规范命名的普通备份文件，不递归或跟随符号链接；用户导出、外部备份、设置与模型不在这个清理范围内。清空全部数据会立即删除这些应用备份。

Recovery spool 的保留期从 manifest 记录的 session 创建时间计算，启动恢复写入不会重置计时。重建失败时，未过期的源分块仍会保留到原定到期时间；缺少、无效或位于未来的创建时间会被保守清理。

设置中的保留策略会在启动时执行，也会在修改历史保留时间后立即执行；应用运行期间还会每日执行一次本机维护。每日维护读取与设置变更同步的最新保留天数，清理过期 recovery spool、History、尚未批准的风格草稿与 usage；research 模式或 owned WAV 重放不启动每日维护，退出开始后不再开始新的维护。spool 清理只删除过期文件，不重建 recovery WAV，也不把记录提升到 History；活动音频 owner 所持有的 session 或文件会跳过，等待中的 owner 不会因调用方等待超时而视为已结束。历史文字、草稿和 usage 可以选择“永久”，这表示不会自动清理，直到你手动删除单条记录或清空全部数据。

## 删除和导出

History 页面提供：

- 导出全部 history JSON（不含音频）；
- 导出保留的训练音频：wav + Qwen JSONL（识别草稿，不含整理结果）；
- 删除单条记录（含对应 gold wav）；
- 清空全部 history、应用创建的数据库迁移备份、recovery audio、gold wav、本地 usage 和本机 `diagnostics/` 目录（包括 `paste-delivery.jsonl` 与 `dictation-performance.jsonl`；不含 `models/`）。

清空操作不可撤销。删除某个服务商的 API Key 是独立操作；若当前 ASR 依赖该密钥，设置会回到未完成状态，未选用的 Groq 密钥移除不会影响另一家服务商，已配置的本机 keyless 路径也会保留。本机模型要在「模型配置」→「本地模型」里单独删除。

## 第三方服务和 telemetry

VoiceFlow 当前不收集 telemetry、广告标识或用户行为分析。网络请求只发往用户选择并配置的 provider；HTTP 429 最多重试两次，网络错误和 5xx 最多重试三次，`Retry-After` 最长等待 60 秒，401/403 不重试。本机 MLX cleanup 请求超时保留其 typed timeout 失败，不由共享队列自动重试。ASR 单次 HTTP 请求最多等待 30 秒；取消会停止排队、重试等待或正在进行的请求。ASR、共同 LLM 整理（包括 Anthropic）及两条视觉请求均不跟随 HTTP 重定向；3xx 返回失败，不向另一个端点重发音频、文字、授权上下文或图像请求体。用户主动下载 MLX ASR 模型时，VoiceFlow 按固定 revision 访问所选模型的公开文件仓库，启动时不静默拉取。SenseVoice 不再提供下载，VoiceFlow 不再访问其 GitHub Releases 归档；已有旧文件只可查看和删除。SenseVoice 的 [模型卡](https://huggingface.co/FunAudioLLM/SenseVoiceSmall)与[权重许可](https://github.com/modelscope/FunASR/blob/main/MODEL_LICENSE)仍适用于这些旧文件。用户需要分别遵守所配置 ASR 与整理服务商及所选模型的许可和服务条款。

正常退出会取消活动 dictation / 文字操作与云请求，停止模型加载并封住新的 sidecar 子进程创建，再通过有界等待关闭本机 sidecar 和清理 `models/audio-tmp/`。这项清理不删除已下载模型、设置、History 或仍在保留期内的恢复录音。

## 安全边界

VoiceFlow 的本地 SQLite 和 recovery audio 默认依赖 macOS 用户账户和应用数据目录的文件权限；应用数据目录、SQLite 文件和 recovery spool 文件会尽量使用 `0700`/`0600` 权限。VoiceFlow 不做应用层加密，因而共享 macOS 用户账户或未加密备份仍可能暴露本地转录。

VoiceFlow 不对 recovery 音频、gold wav 或 History SQLite 做应用层加密；这些文件只受上述文件权限和 macOS 账户 / 磁盘加密保护。早期可选的 `encrypted-spool` 构建 feature 已移除；若磁盘上仍有该构建写入的加密 recovery 文件，VoiceFlow 会报错拒绝读取，不会把密文当作 WAV 发送。

## 可选常开麦克风与本次跳过整理

默认按需打开输入设备。隐藏调试页的「常开麦克风」仅在开发构建中、用户明确开启且已有麦克风权限时才运行；发行构建忽略已保存的开启值，并拒绝该设置字段更新。应用启动不为预热主动请求权限。它持续打开设备，空闲回调直接丢弃样本，不写 spool、不预取、不上传。录音开始后才绑定本次采集 worker，停止或取消后解除绑定；关闭选项、权限撤销和退出关闭空闲流。

在显示屏合上时，打开麦克风流之前会读取 IOKit 的盖板状态和 CoreAudio 设备清单中的名称、UID 与传输类型，以确认所选设备是否为内置麦克风；只有选择身份在读取前后保持一致、设备清单完整且名称唯一时才拒绝启动。已确认的内置输入会提示打开显示屏或选择外接麦克风；外接设备以及身份不完整或有歧义的设备不会据此被拒绝。该检查只读取系统设备元数据，不读取音频内容或保存这些值，也不监视录音期间盖板状态的变化。常开流预热失败只记入现有日志；用户开始听写或麦克风自检时才会看到启动错误。

「本次跳过 AI 整理」仍会调用所选 ASR，并做本地处理和词典替换。AssemblyAI 选择 raw Sync，共同整理模型（含 Ollama、VoiceFlow MLX 与 VoiceFlow llama.cpp）不调用。这个会话标记不写入 History；History 重试使用当前设置。VAD 只过滤允许裁剪的最终 batch 音频，不撤回停止前已发送的实时或预取音频，也不删减完整音频恢复路径。

录音按键监听仅检查 Fn/组合快捷键所需的物理按下、松开和修饰状态；不读取字符、不保存输入文字。Fn 系统冲突通过键盘设置入口交给用户调整，VoiceFlow 不自动更改 macOS 键盘设置。

显式外部 WAV evaluator 可读取 recipe 声明并校验 SHA 的词表、context 和逐 case 本地替换 fixture；它不读取系统窗口、截图、普通 History 或当前用户词典。研究记录区分 provider 原文、过滤/准备稿、adapter 接受稿和最终稿。只有 recipe 的 `capture_provider_candidate:true` 才记录已解析、未通过保护检查的 cleanup reply；关闭时不持久化该未保护 reply，Off/verbatim 不请求或捕获 LLM。认证头、key/key hash、quota/prefetch credential digest 不进入记录。请求字段记录的是客户端构造，不是服务端收到的证明。默认听写没有研究 capture scope；History 的既有 nullable 来源字段和安全 aggregate metrics 不增加原始回复/上下文内容。

显式本机文件评测的 `--models-root` 只作为只读源；`--models-work-root` 必须是仓库外本次新建的独占目录，使用独立副本供现有本机 runtime 处理。它不自动读取正常 App 模型目录或上传音频，也不把校验或加载状态当作识别成功。原始模型文件、生产 marker 与工作目录内派生 tokenizer 的身份分开保留；完成或部分失败的工作目录保留给调用者，不自动递归删除。运行先建立 journal 与取消监听，复制 worker 在有界块间检查取消并在进入凭据/模型请求前 join；可处理 setup 错误与取消记录已写 extent 和保留目录事实。强制进程终止不承诺 durable terminal/resume。研究输入、结果和工作副本均由调用者选择，现有 History、词典、录音和 Keychain 不因此成为语料。

显式 recipe `quality_replay` + TTL 才可通过 `--checkpoint` / `--resume` 保留或读取 SHA 绑定的云文本候选。文件含所选 fixture 文本与历史 request/ASR 来源，放在仓库外；不记录认证值、key hash 或 ambient 环境。每次重放重新运行当前准备与保护/finalizer，不复用旧 final text；历史候选不算当前云质量、性能或可靠性，缺 loaded runtime/precision 身份的本机候选不重放。报告 owner 独立于 checkpoint 获取；后者父目录失效仍尝试记录终态，保留未取得 writer 与路径适用性未知的事实，不猜所有权。报告与 checkpoint 各自原子提交并保留各自 durability 事实，不承诺跨文件事务或强制终止后的完整终态。TTL 到期或年龄未知会明确停止后续凭据/adapter start，而不会退成 cache miss 再发 fresh 请求。普通 History/词典/麦克风不会因此进入缓存。

本机 runtime 的请求临时 WAV 由持有父目录与文件身份的 owner 清理；写入失败、取消或路径替换不会授权删除陌生文件。清理失败会保留描述符和可报告的恢复状态，未解决资源达到上限时停止新临时录音文件。启动/退出仅重试本进程已持有的清理 owner，不再凭 `audio-tmp/*.wav` 通配符认定历史文件归属；旧版本崩溃留下但无所有权证明的文件可能仍在磁盘，需明确检查/手动恢复，不能声称已自动清空。

MLX cleanup performance 诊断在调用线程生成带时间戳和受限字段的记录，再通过容量 256 的有界非阻塞队列交给单一后台 writer；队列满、sink 写入失败或 worker panic 时只发一次不含业务内容的 warning，诊断仍为 best effort。正常退出只有在 ASR owner 与 cleanup 子进程/生成任务均真实终止后才关闭队列并等待 writer drain；有界 shutdown 未能确认终态时保留运行时和 writer 所有权，不把超时当作退出完成。

## 显式研究会话（开发构建）

Default builds have no research sink. The explicit macOS `research-harness` / `--background --research-stdio` entry binds only a finite fixture lease to the real recording, processing and configuration generations; ordinary hotkeys/CLI do not inherit it. Run/case/job UUIDs, target PID and microphone fixture authority are required, and Onboarding leases cannot overlap. Without a separate learning consent, nonempty dictionary/mappings/snippets or enabled context/browser/OCR/learning/always-on microphone still reject prepare. This launch skips background scene refresh, warm capture and old spool/History recovery, and its default run neither loads learned pairs nor starts post-paste learning.

Controlled learning additionally requires explicit selected-state/edit/term fixture UUIDs, declared word pairs and full-field edits, and one exact native mapping/bundle. Only that mapping and selected word range are accepted; browser, OCR, cloud vision, context text upload, snippets and always-on microphone remain disabled. Only selected exact pair keys are read, never an ambient dictionary/History corpus export. Source-surface mismatch, unknown identity or configuration mismatch rejects prepare. Its selected-state content identity and initial ID/count facts describe only the selected keys; baseline requires those rows absent and the test dictionary empty, without automatic clearing. Research recording does not additionally capture automatic screen text. The existing verified-paste/same-field/grant observer owns learning. LearningRecordV1 uses the bounded in-memory sink/private stdio; normal launches gain no per-observation text persistence or term logs. Actual observer and persistence descendants must close before session terminal or final clipboard admission. Whole-field edits, rule hits and counts do not prove ASR correction of the inserted span; the fixture driver programmatic edit is not a human correction.

研究事件只在 256 条有界内存队列内暂存，通过持有进程的专用 stdin/stdout 显式 drain；产品不为此新增 trace 文件、服务器、后台 UI 读取或剪贴板观察。事件包含关联身份、同机单调时间、代际、采样覆盖、过滤后的 ASR 请求诊断标签、清理与交付 owner 的结果。真实有效模型没有来源时保持 unknown；不复制普通指标或诊断里的原始错误。只有 `audio_identity` 明确开启时才计算录音 worker 接受的 16 kHz F32 样本 SHA-256；不输出音频或转写文字。该 hash 不能证明扬声器播放文件等于实际采集。显式 fixture 听写仍遵循现有 History / recovery spool 保留策略；不会读取或汇入个人旧记录。

丢事件会使覆盖不完整。取消请求、远端请求终止和本地流水线终止分别记录，远端终止保持 unknown。只有本地 owner 已终止、录音已关闭、实际或排队交付 writer 均已结束、剪贴板 owner 处理结果已知且无事件丢失时，才允许外部工具进行一次最终剪贴板比较；研究 observer 在事务中不读取临时剪贴板。该准入不能证明文字已插入、剪贴板曾被恢复或模型质量。外部工具保留自己的 AX / DOM 裁判。显式 run 在 `end` 前保留现有操作 lease，避免同一进程启动另一笔交付；关闭 / 过期会撤销授权并进入现有取消 owner，未闭合的资源仍保留未知状态。

四项按需教学（词典学习、上下文 / 看屏幕、选区 / 翻译、场景偏好）分别保存明确确认的教学版本。旧配置默认为未确认；关闭卡片、展示提示或功能成功不构成确认。`acknowledge_guide` 仅在用户明确确认且本地保存成功后更新，保留现有权限、云端选择、学习开关和 onboarded；它不递增录音 / 处理的配置代际，也不把教学确认当成权限或模型验证。普通或旧的设置保存不会擦除或伪造这些确认。真正的模型、权限或处理配置变化仍按原 owner 使已有 trial 失效。
## Normal dictionary learning activity

The native `get_dictionary_learning_audit` command provides a read-only projection that the Dictionary settings page always shows. Normal launches retain at most 128 activity entries in process memory: stable producer codes, opaque IDs, counters and timestamps only. Activity stores no rejected terms, full fields, target PID/title/URL, History content, audio or images. Pair text and saved scope are projected from their existing local store. Original source and historical ignore/undo reasons remain unknown. Native research launch admission disables this normal registry, including prepared undo calls without a task-local trace.

Restart empties activity; eviction and lost updates are explicit. Clear All Data invalidates learning observers before durable work; the retained owner clears this in-memory audit only after the store and diagnostics directory are successfully cleared. A disk-clear error remains an error, and the audit memory is not reported as cleared on that path. This adds no production learning synchronization or ASR configuration-generation change.

The feature-gated `voiceflow-learning-harness` is a separate no-Tauri stdin/stdout executable. It accepts only an explicit private arm root beneath the system temporary directory and creates its settings/SQLite owner there from `Settings::default()`; it does not call normal settings load, `app_data_dir`, Keychain, History import or normal/cloud provider routing. A separately declared WAV task can invoke the existing on-device ASR path. The deterministic text source accepts two to six predeclared complete-field edit states, optional declared follow-up sources, and rights/grant declarations on stdin. `edit_states[].layer=settled` names the predeclared authority layer; it does not mean that each state was read or independently shown stable. Full training/edit fields remain in process memory and are excluded from the arm manifest and training receipts; the production learning row necessarily retains only the selected before/after pair and scoped candidate metadata. Observer receipts distinguish actual polls and consumed declared states from states that were never read after an early stable exit. A stable early exit can still produce a valid owner result from the states actually observed; unread future states and outcomes remain unknown. The local-only candidate path writes an `auto_scoped` rule to the arm's SQLite owner and does not add the target to the global dictionary or save settings after each operation; a preexisting allowed dictionary term remains unchanged. An optional `apply_followup` must match its declared task ID, operation ID, exact text SHA/byte length and scope. It calls the local replacement owner and returns that owner's actual output and hash under explicit `final_output` authority; this is not pipeline-final text, ASR evidence or a native target readback. Its selected-pair usage and dedupe receipt share one SQLite transaction. The declared `undo` calls the production tombstone owner and records its operation receipt in the same transaction; replay does not refresh the tombstone and does not mutate global dictionary settings for an `auto_scoped` rule. Actual local output is limited to 1 KiB before usage or receipt writes. A declared research WAV source can call the existing on-device ASR path, but learning remains disabled unless the complete runtime-attestation gate is satisfied; this does not change the native owned-WAV learning suppression. Human/unknown actors, native insertion, AX, independent target oracle and ASR quality are not established by the deterministic-text path. SQLite main/sidecar paths must remain regular singly-linked files in the canonical arm directory. Observation deduplication uses the existing capped 4096-row receipt table, so replay after eviction is not guaranteed.

The activity limit does not bound persisted pairs. The complete audit projection separately admits at most 1024 rows and 2 MiB of borrowed source UTF-8 before owned copies, including text copied by the existing row mapper such as the tombstone timestamp. Excess returns a typed unavailable result, without truncation, deletion or paging. Exact serde counting also admits at most 16 MiB of snapshot JSON before full encoding, accounting for escape expansion. SQLite internal row allocations, CPU and serialization costs are unmeasured. `stable_revision` means audit-metadata revision stability only: DB/settings mutation intervals remain unobserved and in-flight count is unknown/null. It proves neither cross-store coherence, current permission/applicability, delivery, recognition accuracy nor all-leg persistence success.


#### Optional controlled TextEdit onboarding test

Only the user's explicit action prepares a fixed nonce text fixture. Copying it intentionally changes the clipboard; the later insertion test captures/restores only the test-start clipboard through the existing ownership protocol. The guide never reads or exports clipboard contents. The controlled insertion reads a focused TextEdit field only after native identity admission and requires the exact owned fixture and UTF-16 placeholder selection. Mismatch replies contain bounded codes, never unrelated field text. Only the admitted fixture target identity and exact-readback/restoration facts cross to the onboarding UI; no personal document, screenshot, audio, provider call, History row or training example is created. Product readback and independent oracle evidence are separate. Unknown/current-permission failures invalidate success; clipboard restore scheduling is not a restored fact.


## Explicit fixture final clipboard boundary

Only an explicitly owned research stdio launch may expose the final clipboard association. It contains fixture SHA, sampled native generations and existing run/job/config/recording/processing identities, not clipboard body bytes or text. The digest uses the snapshot bytes already captured by the normal paste owner; the research addition makes no temporary clipboard body request. Normal History, dictionary learning, metrics and diagnostic JSONL gain no clipboard content or new research sink. Final independent clipboard reads belong to the separately authorized external harness after real owner quiescence; no saved JSON or fixed wait enables them. Clipboard reads/writes remain non-atomic, so unknown or changed ownership causes abstention rather than a restoration attempt. This instrumentation does not grant access to normal personal clipboard material.


A separate research-only `--clipboard-guard-general-remote-probe` runs a 10-step recorder-only General clipboard protocol: the parent restores the snapshot only after confirming the child exited and re-checking ownership, and it never reads back or exports the original General clipboard contents or hash. It does not enable the product path: `general_guard_active_for` remains false, and no Host, AX, TIS, `CGEvent`, `Cmd+V`, learning, provider, or model path runs. It does not establish product paste, learning, or quality.


## 设置窗口中的未提交输入

语气、App 规则、服务配置、词典与片段表单的未提交输入仅在当前设置窗口内存中保留，方便跨页返回继续编辑；关闭窗口后丢弃，不写 localStorage、文件或 Keychain，也不因导航发起 provider 请求。明确保存或测试仍使用各自原有数据与凭据通道。折叠授权说明不改变已有授权；展开、阅读和收起也不授予任何权限。清空并保存手动风格样例会移除对应字段；「移除全部样例」还清除该规则的已学习样例并关闭样例批准，需保存后生效。

## Standalone speaker-filter research helper

The phase-1 helper is an explicit local-file research tool, not part of installed VoiceFlow. Its `enroll` and `filter` commands read caller-selected WAV/profile/model files and write private local outputs; they do not capture microphone audio, read History or Keychain, contact cloud services, or create training data. Unix profile, report, and filtered-output files are created with mode `0600`. An enrollment profile stores sensitive speaker embeddings and verification vectors but no source audio; a profile created from public publisher-reference clips is a technical pilot artifact, not a user's biometric enrollment and not authorization for production biometric capture.

The 2026-10-25 native-ASR comparison used local file inputs and no paid cloud API. The tested candidate failed its pilot gate and was not integrated. Production-managed models, daily settings, and the installed app were unchanged; no production speaker-filter setting was added. The private research directory acquired the three small Alkove model files and the fixed Qwen ASR 0.6 model for this test. The existing cleanup path was verified but not modified, loaded, or invoked for the comparison.
