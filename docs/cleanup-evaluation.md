# AI cleanup evaluation protocol

This page describes the evaluation protocol for deterministic local production-path behavior. Fixture references are review targets; they are not provider output, human ratings, runtime/E2E acceptance, or ASR accuracy claims. Real provider, microphone and native target acceptance remain separate from offline contract/adapter tests.

## De-identified corpus

The 161 text fixtures live in [`src-tauri/evals/cleanup-cases.json`](../src-tauri/evals/cleanup-cases.json). Each row has a stable `id`, reporting `group`, `input`, `expected`, optional `reference_variants` and `protected` values, and the production routing fields `cleanup`, `family`, `focus_kind`, and `mode`. The twelve groups cover Chinese, English, mixed language, code, commands, entities, negation, identity, layout, cleanup failure, Auto scenes, and authorized snippets. Inputs include multiline code and form values, empty/silence-like results, filler-only speech, repeated referents, and metadata-looking literal content.

The offline runner is `cleanup_corpus::grouped_production_eval::grouped_160_case_runner_exercises_production_cleanup_fallback_and_guard`. For every case it uses the same `prepare_cleanup_transcript_for_scene` preparation as dictation, then exercises scene mapping and cleanup routing, local failure/Off behavior, and final text guard. Preparation provenance validates the spoken-layout decision and source-range authorized corrections; the final guard checks protected content against that prepared source. This lets the runner recognize layout syntax that production explicitly consumed without exempting those words globally or weakening the 161-case preservation assertions. Identity cases must remain exact. Authorized local correction, layout, and snippet expansion are scored separately from ordinary raw-source invariants.

The shared spoken-layout owner renders clear spoken ordinals as numbered rows and keeps a list preface in its own paragraph. It can ignore a leading ordinal only when its source-bound filler span is empty, the following list restarts at 1 and continues without gaps, and the existing retention directive validates the exact retained items; quoted, code, protected, or substantive source content does not qualify. Separately, it omits an unfinished terminal ordinal only when it is the next sequential number after at least two nonempty items, no retention directive applies, and its body contains only whitespace or sentence-separator punctuation. Any overlap with a protected or quoted/code literal prevents omission; affirmations such as `是啊`, symbols such as `+`, `%`, `/`, or `*`, and complete item text remain content. The proof remains attached to preparation for the same final guard used by dictation and History cleanup. Standalone preface cleanup separately authorizes only an exact initial `嗯` or `呃` token followed by a comma; other filler tokens do not gain this source-range authorization, and the shared final guard is unchanged.

The protected-span guard permits bounded equivalence between Arabic numbers and supported Chinese integer forms for matched source Amount, Date and Number spans, including `百分之N` / `N%`. Arabic decimal fractions compare by reduced value. It retains sign, percentage scale and unit/currency suffix; malformed or out-of-range numeric forms do not receive equivalence, and exact source text remains protected by ordinary matching. Source-span occurrence order and multiplicity remain protected; numeric spans inside code literals remain bound by the exact-literal contract. The guard no longer rejects otherwise-unmatched candidate Amount, Date, Number or Version spans based on candidate-only provenance, and it has no special line-head ordinal waiver. Candidate-only values (including added amounts, duplicates and date/version values) are not established as source-backed by this guard. The cohort and fixtures are external synthetic evidence, not cleanup-corpus rows or provider-quality claims.

Run the deterministic suite with:

```bash
cargo test --manifest-path src-tauri/Cargo.toml --lib grouped_160_case_runner_exercises_production_cleanup_fallback_and_guard
```

Set `VOICEFLOW_CLEANUP_EVAL_REPORT` to write the aggregate report outside the repository. The test itself does not need provider credentials or network access.

## Metrics and interpretation

- Exact reference match accepts `expected` or one of the explicitly declared `reference_variants`. CER and WER use the primary `expected` string. CER lowercases Unicode alphanumeric code points and ignores punctuation and spacing; WER groups contiguous Unicode alphanumeric runs, treating each CJK character as an individual token. These are code-point/token proxies, not grapheme-aware language metrics.
- Declared protected **cases** count rows with at least one `protected` value. Protected **spans** count each listed value separately. The live candidate/final text proxy is a case-insensitive substring-presence check, so it does not enforce token boundaries or prove factual equivalence. The separately reported production final-guard result checks typed source spans, local correction authorization consistency, explicit layout content, and attached demonstrative references during Cleanup (for example, `这个项目` and `那个项目` must retain their reference markers in order). It leaves standalone fillers such as `那个，麻烦你…` and English complementizer phrases such as `I think that it is ready` editable. These checks are narrow lexical / structural heuristics, not semantic verification; Rewrite, Shorten, Formalize, Casualize, and Translate do not lock the Cleanup-only reference markers.
- Mixed-script checks require CJK and Latin characters to remain in a mixed input. Negation coverage is evaluated through the production protected-span/final-guard path and source-preservation checks; equal marker counts do not prove semantic equivalence.
- Identity rewrites must be zero. Snippets and explicitly authorized local corrections/layouts are reported separately because their transformations are intentional.
- Offline latency is local Rust preparation, routing, fallback, and finalization only. It excludes ASR/LLM service time, audio capture, audio encoding, delivery, and operating-system scheduling. Do not compare it with provider latency.

The offline score measures whether deterministic VoiceFlow behavior matches these fixtures. It does not measure hearing, model cleanup quality, user preference, or broad factual correctness.

### Paired filter quality (internal observation)

The `Paired filter quality:` line is a separate descriptive observation emitted after the legacy paired-workflow line when a run has both scoring data and a declared comparison. It uses the original case/repeat union for the two selected jobs and keeps missing peers, replayed rows, failures and unknown evidence in that denominator. If comparison job identities are absent, requested and union counts stay `unknown`; the line reports a `comparison_job_identity_missing` reason instead of treating the unavailable roster as zero. Other reasons distinguish absent filter evidence, replay-ineligible quality, nonterminal runs, mismatched evidence identities and incomplete or invalid quality evidence. Filtered ASR text is scored against the original ASR reference using the existing normalized CER and English WER implementation; raw fallback remains an observation of the original audio. Per-pair CER/WER values and signed on-minus-off differences describe the bound observed pair, not a pass threshold. Missing metric inputs remain unknown because edit rates have no finite universal worst value; CER and WER states also retain their not-applicable versus unknown distinction.

Final bystander leak and per-kind damage span/error counts are shown separately from reviewed arm-unit coverage. Coverage is the number of arms with valid review over the expected two arms per original union row; it is not a denominator for the span/error count. A span/error scalar is shown only when the expected roster is nonempty and every expected arm has a valid review for that measure. Partial or unavailable review therefore leaves the scalar `unknown`, while complete review with no findings is `0`. In particular, `head_damage_spans=3 head_reviewed_arm_units=2/2` describes three observed spans across two fully reviewed arms; it is not an error rate.

The original internal observation remains available in the evaluator console output. The explicit offline entry point below writes a separate `voiceflow_filter_quality_report` and does not change `RunRecord`, `CaseRecord`, recipe, or UI schemas. It reads only its selected evidence sidecar, the two SHA-bound RunRecords, and explicitly named receipt files; it does not follow recorded input paths to open WAVs. It recomputes filtered-ASR CER/WER with the existing scoring core, preserves the selected-job case/repeat union, and reports reviewed final attribution and per-kind damage coverage separately. Human Gold and statistical acceptance remain `unknown` unless the selected receipts and policy establish them. Synthetic points retain a synthetic provenance label and cannot establish a human-quality PASS. Missing CER/WER stays `upper_unbounded` rather than being imputed to 1. The report exposes signed descriptive hierarchical bootstrap intervals for CER/WER deltas in `descriptive_cer_delta` and `descriptive_wer_delta` (10,000 replicates, seed 19). These intervals require speaker/session cluster IDs and provenance and do not establish inferential acceptance. Task73 Clopper–Pearson statistics are emitted separately for false rejects and final bystander events; latency summaries and thresholds remain `unknown` pending Task74.

Each `filter_on` arm may include a `trial_proof` receipt. Its SHA-bound DAG runs protocol → roster → independence declaration → trial receipt → sidecar; it binds the selected run, row, and original audio without hashing the sidecar itself. Eligibility, independence qualification, and event observation are reported separately. A missing event counts conservatively as an error only after Bernoulli qualification; missing proof or qualification leaves the interval unknown. Clopper–Pearson bounds use unique qualified `filter_on` trials with two-sided 95% confidence (`alpha/2 = .025`). Synthetic evidence cannot qualify. For reference, 0 errors in 300 independent trials gives a one-sided upper bound of about 1.2221%. Latency summaries and acceptance gates remain unknown pending Task74.

## Reviewed audio pipeline entry point

`npm run eval:audio -- --help` launches the feature-gated `voiceflow-eval` executable. The Node wrapper owns argument syntax and the unreviewed template; Rust owns schemas, paths, WAV parsing, digests and execution. The executable does not start the desktop App, record the microphone, read Keychain/History, download models or import the user's dictionary. Inputs, reports and checkpoints stay outside the repository, including resolved symlink targets. Reports contain selected fixture text and transcripts; handle them according to the source recordings' data requirements.

```bash
# Create external directories first. The template remains unreviewed.
npm run eval:audio -- --init /absolute/fixtures/manifest.json
# Local validation: no provider credentials, model loading or requests.
npm run eval:audio -- --manifest /absolute/fixtures/manifest.json --validate
# Legacy fixed controls; explicit key environment/file input is required.
npm run eval:audio -- --manifest /absolute/fixtures/manifest.json \
  --asr groq_whisper_large_v3_turbo --cleanup groq_gpt_oss_20b \
  --out /absolute/results/audio.json --gap-ms 250 --run
# Strict corpus/recipe mode, including optional negative fixtures.
npm run eval:audio -- --manifest /absolute/fixtures/speech.json \
  --corpus-sidecar /absolute/fixtures/corpus.json \
  --experiment /absolute/fixtures/recipe.json \
  --non-speech /absolute/fixtures/negative.json --validate
npm run eval:audio -- --manifest /absolute/fixtures/speech.json \
  --corpus-sidecar /absolute/fixtures/corpus.json \
  --experiment /absolute/fixtures/recipe.json \
  --out /absolute/results/run.json --run
```

Direct invocation is `cargo run --locked --manifest-path src-tauri/Cargo.toml --features evaluation --bin voiceflow-eval -- ...`. The normal application CLI remains separate. The wrapper can use an explicitly selected built executable through `VOICEFLOW_EVAL_BIN`. Default tests do not execute live requests.

### Offline paired filter report

The paired filter mode accepts only the two explicit value flags and dispatches before evaluator admission:

```bash
npm run eval:audio -- --filter-evidence /external/filter-evidence-v1.json \
  --filter-report /external/filter-report.json
```

The v1 sidecar binds the original selected-job case/repeat union, both RunRecord SHAs, per-pair `arms.filter_off` / `arms.filter_on` single `row_binding` objects, selected audio, text hashes, and receipt contents. SHA checks alone do not establish evidence: the consumer checks row, text, audio, reference, control-projection, attribution, Gold, owner-trial, and damage bindings against the selected RunRecords and receipt JSON. Missing observations, Gold, comparability, attribution receipts, or damage proof remain unknown; available CER/WER points remain visible, but an unbound control comparison has no paired delta. Damage receipts bind the kind, nonempty UTF-8 reference range and its material hash, the final-text hashes, and each arm assessment. Within one kind, any unknown assessment prevents that arm from counting as fully reviewed for that kind while complete evidence for other kinds remains countable. Declared contradictions are input errors. Reports preserve the full roster, including when `pairs` is empty or incomplete; those rows remain in requested denominators with unknown qualification. A selected job with no rows still fails its identity binding. `observed_subset_spans`, `observed_subset_leaks`, and per-kind `observed_subset_errors` are explicitly counts from reviewed arm units rather than full-roster totals. A synthetic fixture can exercise scoring and binding but never establishes human Gold authenticity. New reports are external, exclusive, mode-0600 files; an existing output is preserved. This report returns `3` for a completed report whose acceptance status is unknown and `1` for new-mode syntax, input, IO or contract errors. It does not decode audio, open `input_paths`, connect admission progress, run a model, or read credentials or Keychain. CER/WER delta intervals use the 10,000-replicate hierarchical bootstrap; acceptance and latency gates remain unknown pending Task74 evidence.

### Offline dictation trace report

The same entry point has a metadata-only report mode:

```bash
npm run eval:audio -- --trace-jsonl /external/dictation-performance.jsonl \
  --trace-report /external/trace-report.json \
  --trace-context /external/short-branches.json
```

`--trace-jsonl` and `--trace-report` are required; `--trace-context` is optional. Trace mode rejects audio, recipe, run, replay, model and provider options and dispatches before regular evaluator admission. It reads at most 10 MiB, 64 KiB per line and 100,000 rows; each terminal may contain at most 256 combined host/reported facts. The report is a new external file (existing output is preserved), bounded to 64 MiB. Input and context must be explicit external files. No App, microphone, audio, model, credential or provider is opened.

The JSONL schema matches the persisted content-free terminal trace: timestamp, generation, fixed class/outcome/cache enums, total duration, host intervals and child-reported durations. Unknown keys/enums, malformed rows, out-of-total or overflowing host intervals, and exceeded limits fail with a line number and no raw input payload. Each terminal retains its original 1-based source line, generation, outcome, class and every repeated fact; generation is not treated as a unique identifier.

Optional context is strict JSON containing the exact input `trace_sha256`, `source` (`synthetic` or `captured_observed`) and `terminals` with 1-based physical `line` plus `branch` (`short`, `long` or `unknown`). Missing context/bindings remain `not_provided`; a slow unclassified row is never inferred to be short. The binding contains no text, audio, clipboard or target identity. Synthetic context remains synthetic evidence. A `preview_only` terminal cannot be marked short.

For each host stage, p50/p95 summarize one per-terminal union duration when that stage was observed; a missing stage is not a zero sample. Each terminal keeps all intervals. Overall host coverage uses interval union across stages, and `unattributed_ms` is total minus that union. Stage summaries overlap and are descriptive, not exclusive causal shares. Child-reported facts are grouped separately by stage and scope because they have no host-clock offsets. Only explicitly known short terminals with total duration **greater than** 8,000 ms enter `slow_short_terminals`; unknown slow membership is listed separately. Failure, cancellation and unconfirmed outcomes remain in the terminal rows. These reports describe supplied metadata only; they do not establish App delivery, actual capture branch, model performance, cold/warm state or a slow-request cause.

Evaluation latency quantiles share linear interpolation at `(n-1)*p` over finite, nonnegative samples. Empty samples serialize as `null`; corpus latency fields likewise use `null` and print as unavailable. Product metrics in `metrics.rs` retain their separate nearest-rank definition. File-evaluation submit, readback and stop-to-insert remain not applicable.

The legacy manifest keeps `schema_version: 1`, `provenance: {kind, note, reviewed}` and `cases`. Provenance kind is `human_recorded` or `synthetic`, with reviewed source/rights/de-identification notes. Each case supplies unique `id`, adjacent `.wav` filename, nonempty verbatim `reference`, reviewed `expected_final`, `scenario`, `family`, `focus_kind` and cleanup intensity (`auto/off/light/standard/heavy`). Optional `protected` and `reference_variants` apply to cleanup. A synthetic smoke fixture does not become human gold because its provenance was reviewed.

WAVs must be complete RIFF files with one format/data chunk, 16 kHz mono PCM16, nonempty and at most ten minutes/25 MiB. Rust decodes every PCM sample and rejects malformed tails. Each manifest remains 1–200 cases/1 MiB; larger corpora use declared shards. The entire selection validates before credentials or providers. Validated WAV bytes are retained for execution, with WAV SHA256, PCM SHA256, sample count and format; PCM digest hashes the little-endian signed 16-bit sample sequence. Reference digest hashes the exact UTF-8 reference text.

### Optional admission progress socket

`--admission-progress-socket /private/tmp/caller-owned/p.sock` is an explicit **validate-only** Unix option. The receiver must already be a canonical external Unix datagram socket under a caller-owned directory with mode0700; the caller owns its creation, receipt capture and cleanup. The selected pathname plus NUL must fit the platform `sockaddr_un.sun_path` (104 bytes on macOS). Duplicate/missing choices, the old boolean `--admission-progress`, and use without explicit `--validate` or with `--run` reject. The Node wrapper forwards the selected locator; Rust owns socket/path admission. No default sink, environment opt-in, model download or runtime launch is added.

```bash
# Caller must already own/drain this short-path receiver; validation creates none.
voiceflow-eval --manifest /external/fixtures/speech.json \
  --corpus-sidecar /external/fixtures/corpus.json --experiment /external/fixtures/recipe.json \
  --cleanup-candidate-manifest /external/cleanup-candidate-v1.json \
  --cleanup-work-root /external/new-cleanup-workspace --validate --json \
  --admission-progress-socket /private/tmp/caller-owned/p.sock
```

The evaluator owns one fresh unbound nonblocking sender. It connects once and makes one `MSG_DONTWAIT` send per packet, without retry, poll, flush, acknowledgement, worker or changes to inherited FD flags/global signals. Datagram enqueue does not prove receiver observation or authenticate the sender/model. Each compact JSON object plus LF is at most1024 bytes; at most128 packets/128KiB are accepted, including reserved truncation/terminal space. The schema is the typed closed `Record` in `evaluation/admission_progress.rs` (`v:1`, `kind:"vf14_admission_progress"`). Its six events are `admission_begin`, `scope_begin`, `scope_sample`, `scope_end`, `truncated`, `admission_end`. Sequence is per invocation and contiguous among accepted sends. Unknown/missing/duplicate fields, unknown variants/versions, malformed/trailing bytes and truncated datagrams are invalid.

Input, preflight, local-ASR, local-cleanup and output/replay phases report begin/end boundaries. Preflight additionally reports repository/lock/executable/platform groups. Cleanup reports candidate, fixed-pins, model-files, runtime-sources, version-shim, exact-inventories and workspace-parent groups. Only fixed-pins/model-files/runtime-sources sample bytes, at most16 fractional-coverage buckets per group; skipped buckets emit the latest reached sample once. Declared lengths/counts come from existing parsed inventories, not extra content/stat passes. Unknown totals are null, distinct from zero. The defined full schedule is82 records; the hard128-record limit reserves truncation and terminal even if the schedule is violated.

`cleanup` is a **cleanup-admission-only cumulative** counter snapshot, initialized once on entering that phase. Other admission IO/auxiliary hashes are not included. `read_bytes` counts actual returned content reads (initial candidate capture becomes visible when its bounded read returns); `file_hash_feed_bytes` counts bytes supplied to existing file-content SHA calls, including candidate pin and final manifest rehash. No hash is repeated for diagnostics. `verified_file_bytes`/`verified_files` advance only after complete length/digest and held/current-path checks pass. Group-local entry counts/ordinals reset on that group's begin; per-file facts remain provisional if later template/inventory/Plan admission fails. Template UTF-8, identity framing, PCM and other application hash feeds are excluded, so these counters are not a full application hash-feed or physical disk-IO total. Expected pins, loaded precision and runtime readiness stay separate.

The final `admission_end` separates admission result from diagnostic state. Quota/counter failures suppress normal progress and retain at mostone truncation plus terminal; IO/serialization failures stop all sends and may leave no terminal. Every existing input check still runs. An obtained full `InputError` remains primary, including its selected path/reason and semantic exit classification; if admission otherwise succeeds but required diagnostics fail, it returns `admission_diagnostic_failure` instead of success JSON. Setup failure is `admission_diagnostic_unavailable` before input admission. There is no recursive error packet or stdout fallback. Normal stdout and full terminal error JSON remain on their existing streams; their delivery/liveness can still fail or block. The new bound concerns intentional producer queue waiting/userspace state, not arbitrary kernel scheduling, inherited stream liveness or unobserved close results.

Missing/dropped/out-of-order packets, truncation or an absent admission terminal mean partial/unknown trace coverage. The last complete received sample is a lower bound at its own monotonic timestamp, not the exact active file/phase at SIGINT. Zero verified bytes can coexist with partial shard hashing. Completion proves admission only; partial rates cannot establish a general completion upper bound, explain an earlier interruption or certify model/ASR/quality behavior. Real socket/CLI/model acceptance remains subject to independently bound verification; this source addition supplies no prior runtime credit.

### Corpus, negative and recipe contracts

The strict contracts are owned by [`evaluation/contracts.rs`](../src-tauri/src/evaluation/contracts.rs); unsupported fields are rejected, including tagged variants. Artifact names are `corpus_sidecar`, `non_speech_index`, `run_recipe`, `run_input_identity` and `run_record`. V1 speech uses outer `schema_version:1`; V2 negative and V3 ASR-only versions are described below. Baseline identity has its own versioned sub-schema, described under artifact identity.

- `CorpusSidecarV1` declares `corpus_id`, manifest relative paths/SHA256, and complete per-case manifest/WAV/PCM/reference identity. Cases include reviewed source kind, rights-review ID, speaker/session/template IDs, `split` (`dev/test/train`), language (`zh/en/mixed`), annotation revision and `conditions: {noise, microphone, speaking_style}`. Every speech case must occur exactly once. Source kind must match manifest provenance. Speaker, session, template and identical PCM groups cannot cross splits. The explicitly selected `--manifest` must belong to this sidecar; all declared shards validate.
- `NonSpeechIndexV1` has reviewed provenance and cases with `case_id`, `adjacent_wav`, `audio_sha256`, category (`silence/noise/music/non_speech`) and `source_review_id`. It uses the same WAV/path validator without a fabricated speech reference. Negative IDs must remain unique across the entire selection.
- `RunRecipeV1` binds the exact sidecar SHA and declares track, jobs and optional GUI fixture. Each job records product/artifact identity, ASR candidate, mode, recognition language, decode controls, vocabulary/context, cleanup, local-rule revision, profile-state ID, repeats, pacing and request/deadline budget. `--corpus-sidecar` is an explicit locator because the recipe carries a digest rather than a path. Recipe controls cannot mix with legacy `--asr/--cleanup/--gap-ms` flags.

Visible bounds are 20 manifests, 1000 combined speech/negative cases, 512 MiB total audio, 32 jobs, 20 repeats per job, 10,000 expanded case/job/repeat records and a 256 MiB serialized run record. Each job declares maximum cases/requests/retries/deadline; the request budget must cover selected ASR calls, cleanup calls and the existing bounded cleanup retry. No directory scan discovers extra data.

### Implemented recipe execution

Recipe `--run` uses the same production ASR and cleanup adapters, preparation, routing and finalizer as the legacy evaluator. Preparation consumes the shared non-test preparation owner behind `prepare_cleanup_transcript_for_scene`, also used by dictation and writing preview, retaining its original correction source, authorizations and protected pairs through the final guard. Explicit fixture snippets remain a separate exact-expansion bypass; they do not add ambient terms or run ordinary spoken-layout transformations on the expansion. Recipe execution verifies the embedded VoiceFlow build-source/version identity, `file_adapter`, dictation/verbatim, auto/zh/en recognition, explicit vocabulary/context fixtures and declared local rule factors at revision `voiceflow-production-v1`. Custom decoder controls remain unsupported. The empty baseline remains `local_rules: {dictionary_replacements:false, fuzzy:false, spoken_layout:true, revision:"voiceflow-production-v1"}`. Cleanup is off/verbatim, or an existing allowlisted cleanup candidate. Off/verbatim makes no LLM request and requires no cleanup key; a scene that routes locally also requires no cleanup key.

Cloud ASR IDs are `groq_whisper_large_v3_turbo`, `groq_whisper_large_v3`, `openai_gpt_transcribe` and `qwen3_asr_flash_dashscope`; the two local recipe IDs use the explicit source/workspace path below. Cleanup IDs are `groq_gpt_oss_120b`, `groq_gpt_oss_20b`, `openai_gpt_4o_mini` and `qwen_plus_dashscope`. Cloud execution accepts only explicit `VOICEFLOW_EVAL_<PROVIDER>_API_KEY` or `_KEY_FILE` (`GROQ`, `OPENAI`, `QWEN`); key contents and ambient environment are not recorded. Recipe model/endpoint selection is fixed and cannot be changed through legacy model overrides.

Unsupported explicit language/context/vocabulary factors reject before credentials according to the producing adapter capability contract. Custom decode, unknown rule revisions and GUI/learning execution remain unsupported. Native streaming/Assembly routes may produce request facts in ordinary adapters but are not selectable file-evaluator candidates in this batch. Recipe SHA replay is an explicit file-adapter policy, described below. Unsupported options do not silently become validation-only runs or unsupported requests.

Local recipe ASR candidates `local_qwen3_asr_0_6b` and `local_qwen3_asr_1_7b` map to the existing production model IDs/pinned MLX revisions. Select an existing **read-only source** root containing `<model-id>/` with all nine pinned files using `--models-root`. A live run additionally requires `--models-work-root` naming a **new, exclusive external directory**; missing roots fail before credentials or materialization. This is a fresh-run path; it never resumes an existing workspace, installs/downloads weights, reads the normal App model directory implicitly, or falls back to cloud ASR. These candidates require `--experiment`; legacy `--asr/--cleanup` keeps its cloud-only fixed controls. SenseVoice remains a legacy non-executable model.

```sh
npm run eval:audio -- --manifest /external/speech.json --corpus-sidecar /external/corpus.json \
  --experiment /external/local-recipe.json --models-root /external/models-original --validate
npm run eval:audio -- --manifest /external/speech.json --corpus-sidecar /external/corpus.json \
  --experiment /external/local-recipe.json --models-root /external/models-original \
  --models-work-root /external/new-exclusive-workspace --out /external/new-run.json --run
```

Validation hashes the declared pinned source files through the shared production integrity owner, retains immutable descriptor/identity facts and rejects missing/corrupt/symlink inputs. It does not copy files, write markers, launch a sidecar or load a model. A supplied work/output target must not already exist, including during validation. With `--run`, source descriptors produce independent streamed copies once per model/run; no source hard links or source mutations. The workspace contains the exact production marker plus a materialization recipe; partial failures and completed working trees are retained. The existing Swift loader regenerates `tokenizer.json` only in this mutable copy. Its separately observed bounded digest is a derived artifact, never labelled a publisher file. A replacement/moved root cannot authorize workspace cleanup by path.

A complete initial RunRecord journal and cancellation listener precede materialization and credential resolution. Materialization runs in a joined blocking worker, checking cooperative cancellation at every bounded (at most 1 MiB) read/write and file boundary. The run waits for that worker to finish before recording a terminal setup outcome or entering credential/provider execution. Setup facts separately record materialization, worker join, credential resolution, per-file written extents/state and retained partial workspace identity/applicability. A handled copy error or cancellation preserves these facts in the existing journal; errors also retain the same typed setup facts if report persistence fails. Setup cancellation makes zero adapter attempts and skips keys/providers; runtime load/inference retain the existing cancellable path. Validation still writes no journal or workspace. Existing workspaces are not resumable: forced termination/crash can leave partial state without a durable terminal or complete SHA checkpoint, which remains outside this fresh-run contract.

The real `OnDeviceAsrProvider` and canonical-root `shared_runtime` own execution, serialization, private audio, cancellation and child termination. Request WAV owners hold file/parent descriptors and use exclusive quarantine plus identity checks for cleanup; replacement paths preserve foreign content and failed owners remain retained. Startup/shutdown retries only known held owners, leaving historical unproved `.wav` orphans untouched. Workspace teardown invokes the runtime child owner without a pathname glob purge. Local ASR needs no cloud key; cleanup off/verbatim also needs no LLM key or request. Language auto omits the IPC field, zh/en use the existing language contract. Local decoder vocabulary/context controls are unsupported and rejected before keys/invocation; explicit post-recognition local rule fixtures remain separate. Custom beam/temperature remain unsupported. Old WAV limits are unchanged. Configured/checksummed files do not establish runtime handshake, load or inference. Per-case `local_model` records pinned source/copied/marker identity and declared precision separately from unknown loaded precision/derived tokenizer facts; `local_runtime` records owner-emitted phase/identity/coverage events. This evaluation capture remains separate from ordinary privacy-safe local ASR stage diagnostics, which record bounded operation stages and elapsed time without transcript, audio, prompt, token IDs, paths or raw errors. ### Standalone speaker-filter research helper (2026-10-25)

`src-tauri/speaker-filter/` is a standalone Rust CPU helper with file-based `enroll`, `filter`, and bounded `serve` commands; it has no Tauri dependency or production call path. Helper `--paced` wall-clock RTF includes intentional replay waits, so it cannot be compared with the compute RTF threshold of `≤ 0.2`. Unpaced helper RTF describes native compute and buffering only; it does not measure stop-to-drain `≤ 200 ms` or complete end-to-end latency.

The exploratory paired run used 90 prepared public-publisher-reference cases and produced 180 local native-ASR rows for raw and G0-filtered audio, spanning three target publisher speaker IDs and two interferer IDs. It was not a locked independent cohort or release qualification. Twelve of those 90 cases were other-only; all 12 G0 ASR results were nonempty, failing the pilot's intended no-more-than-1% nonempty-output criterion for this candidate. A G0 example also lost the initial short Chinese word `我`.
